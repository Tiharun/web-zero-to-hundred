# P1 용어

### 인터넷
- 처음 등장: [P1 Day 1](#/day/p1-d01)

전 세계의 컴퓨터를 서로 연결한 거대한 통신망이에요. 메신저, 온라인 게임, 이메일, 웹이 모두 이 통신망 위에서 움직여요. 그래서 인터넷과 웹은 같은 말이 아니에요. 인터넷은 길이고, 웹은 그 길을 쓰는 서비스 가운데 하나예요.

### 웹
- 처음 등장: [P1 Day 1](#/day/p1-d01)

인터넷 위에서 웹페이지를 주고받고, 링크로 서로 이어 주는 서비스예요. 정식 이름은 World Wide Web(줄여서 WWW)이에요. 우리가 브라우저로 보는 모든 사이트가 웹에 속해요.

### 브라우저
- 처음 등장: [P1 Day 1](#/day/p1-d01)

웹페이지 파일을 받아 와서 사람이 볼 수 있는 화면으로 그려 주는 프로그램이에요. Windows 11에는 Microsoft Edge가 기본으로 들어 있고, Google Chrome도 많이 써요. 같은 HTML 파일이면 Edge와 Chrome에서 거의 똑같이 보여요.

### 서버
- 처음 등장: [P1 Day 1](#/day/p1-d01)

웹페이지 파일 같은 자료를 보관하고 있다가, 요청이 오면 보내 주는 컴퓨터(또는 프로그램)예요. 브라우저가 주소를 보내 "이 페이지 주세요"라고 요청하면, 서버가 그 주소에 맞는 파일을 돌려줘요. P1의 마지막에는 GitHub Pages라는 서버에 내 사이트를 올려요.

### URL
- 처음 등장: [P1 Day 1](#/day/p1-d01)

인터넷이나 내 컴퓨터에서 자료가 있는 위치를 가리키는 주소예요. `https://`로 시작하면 인터넷 너머의 서버에서, `file:///`로 시작하면 내 컴퓨터 안에서 파일을 가져와요. 브라우저 맨 위의 주소 표시줄에 보이는 글자가 URL이에요.

### 웹페이지
- 처음 등장: [P1 Day 1](#/day/p1-d01)

브라우저 화면 한 장에 보이는 문서 하나예요. 보통 HTML 파일 하나가 웹페이지 하나가 돼요. 예를 들어 `hello.html` 파일을 브라우저로 열면 웹페이지 한 장이 보여요.

### 웹사이트
- 처음 등장: [P1 Day 1](#/day/p1-d01)

서로 링크로 이어진 웹페이지 여러 장을 한 주소 아래에 모아 둔 묶음이에요. 홈, 소개, 영상 목록처럼 여러 페이지가 함께 하나의 사이트를 이뤄요. P1에서 만드는 "나의 크리에이터 홈페이지"가 웹사이트예요.

### HTML
- 처음 등장: [P1 Day 1](#/day/p1-d01)

웹페이지의 내용과 구조를 적는 언어예요. "여기는 큰 제목, 여기는 문단"처럼 꺾쇠 괄호 `< >`로 감싼 표시를 글자 사이에 넣어서 써요. HTML 파일은 글자로만 된 파일이라서 메모장 같은 텍스트 편집기로도 만들 수 있어요. 이름은 HyperText Markup Language의 머리글자예요.

### 코드
- 처음 등장: [P1 Day 1](#/day/p1-d01)

컴퓨터가 알아듣는 규칙(언어)에 맞춰 쓴 글이에요. HTML로 쓴 웹페이지 내용이 대표적인 코드이고, 앞으로 배울 여러 언어로 쓴 명령도 모두 코드예요. 코드는 보통 텍스트 편집기에 글자로 쓰고 파일로 저장해요.

### 텍스트 편집기
- 처음 등장: [P1 Day 1](#/day/p1-d01)

글꼴·색 같은 꾸밈 없이 글자만 쓰고 저장하는 프로그램이에요. Windows의 메모장이 대표적이고, Day 2에 설치하는 VS Code도 코드를 쓰기 좋게 만든 텍스트 편집기예요. 워드나 한글(HWP) 같은 문서 프로그램은 꾸밈 정보를 함께 저장하므로 HTML 파일을 만들 때 쓰지 않아요.

### 파일
- 처음 등장: [P1 Day 1](#/day/p1-d01)

컴퓨터에 이름을 붙여 저장한 자료 한 덩어리예요. 글, 사진, 음악, 프로그램이 모두 파일이에요. 파일 이름은 보통 `이름.확장자` 모양이에요.

### 폴더
- 처음 등장: [P1 Day 1](#/day/p1-d01)

파일과 다른 폴더를 담아 정리하는 상자예요. 폴더 안에 폴더를 넣을 수 있어서, `C:\dev` 안에 `hello` 폴더를 두는 식으로 층층이 정리해요. 디렉터리(directory)라고 부르기도 해요.

### 확장자
- 처음 등장: [P1 Day 1](#/day/p1-d01)

파일 이름에서 마지막 점(`.`) 뒤에 붙은 글자예요. `hello.html`의 확장자는 `html`이고, Windows는 확장자를 보고 이 파일을 어떤 앱으로 열지 정해요. 점이 여러 개면 마지막 점 뒤만 확장자라서, `hello.html.txt`는 웹페이지가 아니라 텍스트 문서(`.txt`)예요. Windows 메뉴에서는 "파일 확장명"이라고 불러요.

### 경로
- 처음 등장: [P1 Day 1](#/day/p1-d01)

파일이나 폴더가 어디에 있는지를 드라이브부터 차례로 적은 주소예요. `C:\dev\hello\hello.html`은 "C 드라이브 → dev 폴더 → hello 폴더 → hello.html 파일"이라는 뜻이에요. Windows는 폴더 사이를 `\`(역슬래시)로 구분하고, 한국어 키보드에서는 `₩` 키로 입력해요.

### UTF-8
- 처음 등장: [P1 Day 1](#/day/p1-d01)

글자를 컴퓨터가 저장하는 숫자로 바꾸는 방식(인코딩) 가운데, 한글·영어·이모지까지 전 세계 글자를 모두 담을 수 있는 표준이에요. 웹페이지는 UTF-8로 저장하고 HTML 안에도 `<meta charset="utf-8">`이라고 적어 두는 것이 기본이에요. 저장 방식과 적어 둔 방식이 서로 다르면 한글이 `�`처럼 깨져 보여요.

## Day 2

### VS Code
- 처음 등장: [P1 Day 2](#/day/p1-d02)

Microsoft가 무료로 만든 코드 편집기예요. 정식 이름은 Visual Studio Code예요. 메모장처럼 글자를 쓰고 저장하는 텍스트 편집기이지만, 코드에 색을 입혀 주고 폴더 전체를 한 창에서 다루며, 확장 프로그램으로 기능을 더할 수 있어요. 이 교재의 모든 프로젝트는 VS Code로 만들어요.

### 확장 프로그램
- 처음 등장: [P1 Day 2](#/day/p1-d02)

프로그램에 나중에 끼워 넣어 기능을 더하는 작은 프로그램이에요. VS Code에서는 왼쪽의 확장 아이콘(`Ctrl + Shift + X`)에서 찾아 설치해요. 예를 들어 한국어 팩은 메뉴를 한국어로 바꾸고, Live Preview는 웹페이지 미리 보기를 더해 줘요. 이름이 비슷한 가짜도 있어서 만든 곳(게시자)을 꼭 확인해요.

### 명령 팔레트
- 처음 등장: [P1 Day 2](#/day/p1-d02)

VS Code의 거의 모든 기능을 이름으로 찾아 실행하는 입력 칸이에요. `Ctrl + Shift + P`를 누르면 화면 위쪽에 열리고, `Live Preview: Show Preview`처럼 기능 이름 일부를 치면 목록이 좁혀져요. 메뉴 위치를 몰라도 이름만 알면 실행할 수 있어서 편리해요.

### 자동 저장
- 처음 등장: [P1 Day 2](#/day/p1-d02)

고친 내용을 `Ctrl + S`를 누르지 않아도 잠시 뒤 저절로 파일에 저장해 주는 기능이에요. VS Code에서는 **파일 → 자동 저장**으로 켜고 끄며, 켜져 있으면 메뉴 이름 앞에 체크가 보여요. 꺼져 있을 때는 탭 이름 옆의 동그라미(●)가 "아직 저장하지 않았어요"라는 표시예요.

### Live Preview
- 처음 등장: [P1 Day 2](#/day/p1-d02)

Microsoft가 만든 VS Code 확장 프로그램으로, 지금 만드는 웹페이지를 VS Code 안이나 브라우저에서 바로 보여 줘요. 내 컴퓨터 안에 작은 서버를 띄워서 `http://127.0.0.1:3000/` 같은 주소로 파일을 보내 주는 방식이에요. 파일을 더블클릭해 여는 것과 달리 진짜 웹 주소처럼 동작해서, `fetch`로 파일을 읽는 페이지(Day 25부터)도 열 수 있어요.

## Day 3

### 태그
- 처음 등장: [P1 Day 3](#/day/p1-d03)

HTML에서 꺾쇠 괄호로 감싼 표시예요. `<p>`처럼 여는 태그와 `</p>`처럼 앞에 `/`가 붙은 닫는 태그가 짝을 이뤄 "여기부터 여기까지가 문단이에요"라고 알려 줘요. `<meta>`나 `<img>`처럼 닫는 태그가 없는 것도 있어요.

### 요소
- 처음 등장: [P1 Day 3](#/day/p1-d03)

여는 태그, 내용, 닫는 태그를 합친 HTML의 한 덩어리예요. 예를 들어 `<h1>안녕하세요</h1>` 전체가 h1 요소 하나예요. 요소 안에 다른 요소를 넣을 수 있어서, 웹페이지는 요소가 겹겹이 들어 있는 구조가 돼요.

### 속성
- 처음 등장: [P1 Day 3](#/day/p1-d03)

여는 태그 안에 `이름="값"` 모양으로 적어 요소에 정보를 더하는 것이에요. `<html lang="ko">`의 `lang="ko"`는 "이 문서는 한국어예요"라는 속성이고, `<img src="…">`의 `src`는 그림 파일의 위치를 알려 줘요. 값은 큰따옴표로 감싸요.

### DOCTYPE
- 처음 등장: [P1 Day 3](#/day/p1-d03)

HTML 파일 맨 첫 줄에 쓰는 `<!doctype html>` 선언이에요. 브라우저에게 "이 문서는 요즘 표준 HTML이에요"라고 알려서 옛날 방식으로 그리지 않게 해요. 대문자(`<!DOCTYPE html>`)로 써도 뜻이 같아요.

### 주석
- 처음 등장: [P1 Day 3](#/day/p1-d03)

코드 안에 사람이 읽으려고 남기는 메모로, 화면에도 실행에도 영향을 주지 않아요. HTML은 `<!-- 메모 -->`, CSS는 `/* 메모 */`, JavaScript는 `// 메모`로 써요. 나중의 나나 다른 사람이 "왜 이렇게 했는지" 알 수 있게 해 줘요.

### Emmet
- 처음 등장: [P1 Day 3](#/day/p1-d03)

짧은 약어를 입력하면 긴 HTML 코드로 펼쳐 주는 기능이에요. VS Code에 기본으로 들어 있어서, `.html` 파일 첫 줄에 `!`를 치고 `Tab`을 누르면 문서 뼈대가 한 번에 만들어져요. 타이핑을 줄여 주지만, 만들어진 코드의 뜻은 직접 알고 있어야 해요.

### 들여쓰기
- 처음 등장: [P1 Day 3](#/day/p1-d03)

줄 앞에 빈칸을 넣어 안쪽에 들어 있는 코드를 한눈에 보이게 하는 것이에요. 이 교재는 한 단계마다 스페이스 2칸을 써요. HTML·CSS·JavaScript에서는 들여쓰기가 화면 결과를 바꾸지 않지만, 닫는 태그나 중괄호를 빠뜨린 곳을 찾기 쉽게 해 줘요.

## Day 4

### 링크
- 처음 등장: [P1 Day 4](#/day/p1-d04)

누르면 다른 웹페이지나 파일로 넘어가게 하는 연결이에요. HTML에서는 `<a href="about.html">소개</a>`처럼 `a` 요소로 만들고, `href` 속성에 갈 곳의 주소를 적어요. 링크로 이어진 페이지들이 모여 웹사이트가 돼요.

### 절대 경로
- 처음 등장: [P1 Day 4](#/day/p1-d04)

시작점부터 끝까지 전부 적어서, 어느 파일에서 쓰든 같은 곳을 가리키는 주소예요. 웹에서는 `https://developer.mozilla.org/ko/`처럼 `https://`부터 쓴 주소가 절대 경로예요. 다른 사이트로 가는 링크에 쓰고, 내 사이트 안의 파일끼리는 상대 경로를 써요.

### 상대 경로
- 처음 등장: [P1 Day 4](#/day/p1-d04)

지금 파일이 있는 폴더를 기준으로 다른 파일의 위치를 적는 주소예요. 같은 폴더면 `about.html`, 안쪽 폴더면 `images/profile.svg`, 한 칸 위 폴더면 `../favicon.svg`처럼 써요. 프로젝트 폴더를 통째로 다른 곳(배포 서버)에 옮겨도 그대로 동작해서 내 사이트 안의 링크·그림에 써요.

### 목록
- 처음 등장: [P1 Day 4](#/day/p1-d04)

여러 항목을 차례로 늘어놓는 HTML 요소예요. 순서가 상관없으면 `ul`(점 목록), 순서가 중요하면 `ol`(번호 목록)을 쓰고, 항목 하나하나는 `li`로 감싸요. 사이트 메뉴도 링크를 담은 목록으로 만들어요.

### 대소문자 구분
- 처음 등장: [P1 Day 4](#/day/p1-d04)

영어 대문자와 소문자를 서로 다른 글자로 보는 것이에요. Windows는 파일 이름에서 대소문자를 구분하지 않아 `About.html`과 `about.html`을 같은 파일로 보지만, 웹 서버(예: GitHub Pages)는 구분해서 다른 파일로 봐요. 그래서 내 컴퓨터에서 되던 링크가 배포 뒤 깨질 수 있어, 파일 이름은 처음부터 소문자로만 지어요.

## Day 5

### SVG
- 처음 등장: [P1 Day 5](#/day/p1-d05)

점·선·도형을 글자(코드)로 적어 그리는 그림 형식이에요. 이름은 Scalable Vector Graphics의 머리글자이고, 아무리 크게 키워도 흐려지지 않아 로고·아이콘에 잘 맞아요. 글자로 된 파일이라 VS Code로 열어 내용을 읽고 고칠 수 있어요.

### 대체 텍스트
- 처음 등장: [P1 Day 5](#/day/p1-d05)

그림을 볼 수 없을 때 그림 대신 전해지는 글이에요. `<img>`의 `alt` 속성에 적고, 스크린 리더가 소리 내어 읽거나 그림 파일을 못 불러왔을 때 화면에 보여요. 그림이 전하는 내용을 짧게 쓰고, 옆 글자와 같은 뜻의 장식 그림이면 `alt=""`로 비워 둬요.

### 접근성
- 처음 등장: [P1 Day 5](#/day/p1-d05)

장애가 있거나 환경이 다른 사람도 웹사이트를 똑같이 쓸 수 있게 만드는 것이에요. 그림에 대체 텍스트 달기, 키보드만으로도 조작되게 하기, 글자와 배경의 색 차이를 충분히 두기 등이 모두 접근성이에요. 영어로는 accessibility라서 줄여서 a11y라고도 써요.

### 스크린 리더
- 처음 등장: [P1 Day 5](#/day/p1-d05)

화면의 글자와 구조를 소리(또는 점자)로 읽어 주는 프로그램이에요. 앞이 잘 보이지 않는 사람이 웹을 쓸 때 사용하며, Windows에는 내레이터가 들어 있어요. 스크린 리더는 HTML 요소의 종류와 대체 텍스트, ARIA 속성을 보고 내용을 설명해 줘요.

### 상위 폴더
- 처음 등장: [P1 Day 5](#/day/p1-d05)

지금 폴더를 담고 있는 한 칸 위의 폴더예요. 상대 경로에서는 `../`로 적고, `../../`는 두 칸 위예요. 예를 들어 `C:\dev\my-creator-site\overlay\countdown.html`에서 `../favicon.svg`는 `C:\dev\my-creator-site\favicon.svg`를 가리켜요. 지금 폴더 자체는 `./`로 적어요.

## Day 6

### 시맨틱 HTML
- 처음 등장: [P1 Day 6](#/day/p1-d06)

모양이 아니라 뜻에 맞는 요소로 페이지를 짜는 방식이에요. 머리글은 `header`, 메뉴는 `nav`, 본문은 `main`, 바닥글은 `footer`처럼 쓰면 스크린 리더와 검색 엔진이 페이지 구조를 알아볼 수 있어요. 아무 뜻이 없는 `div`·`span`은 알맞은 요소가 없을 때만 써요.

### 블록 요소
- 처음 등장: [P1 Day 6](#/day/p1-d06)

화면에서 한 줄을 통째로 차지하고, 다음 요소를 아래 줄로 밀어내는 요소예요. `h1`, `p`, `div`, `section`, `ul` 등이 블록 요소예요. 의미 없이 여러 요소를 묶는 블록 상자가 필요할 때 `div`를 써요.

### 인라인 요소
- 처음 등장: [P1 Day 6](#/day/p1-d06)

글자 흐름 안에 끼어 들어가서 필요한 만큼만 자리를 차지하는 요소예요. `a`, `strong`, `em`, `span`, `img` 등이 인라인 요소라서 앞뒤 글자와 같은 줄에 놓여요. 글자 일부만 따로 묶을 때 아무 뜻이 없는 `span`을 써요.

### 문자 참조
- 처음 등장: [P1 Day 6](#/day/p1-d06)

HTML에서 특별한 글자를 `&이름;` 모양으로 적는 방법이에요. `&copy;`는 ©, `&lt;`는 `<`, `&gt;`는 `>`, `&amp;`는 `&`가 돼요. 꺾쇠처럼 태그로 오해받을 글자나 키보드로 치기 어려운 기호를 쓸 때 사용하고, 끝의 `;`를 빠뜨리지 않아요.

### 개발자 도구
- 처음 등장: [P1 Day 6](#/day/p1-d06)

브라우저에 들어 있는, 웹페이지의 속을 들여다보고 실험하는 도구예요. `F12`(또는 `Ctrl + Shift + I`)로 열고, Elements에서 HTML 구조, Console에서 JavaScript 결과와 오류, Network에서 주고받은 파일을 볼 수 있어요. 여기서 고친 내용은 화면에만 잠깐 적용되고 내 파일은 바뀌지 않아요.

## Day 7

### 버전 관리
- 처음 등장: [P1 Day 7](#/day/p1-d07)

파일이 바뀐 기록을 시점마다 남겨 두고, 필요하면 예전 상태로 되돌리거나 비교할 수 있게 관리하는 것이에요. "최종", "진짜최종" 같은 복사본을 만드는 대신 한 폴더 안에서 기록만 쌓아요. 여러 사람이 같은 코드를 함께 고칠 때도 꼭 필요해요.

### Git
- 처음 등장: [P1 Day 7](#/day/p1-d07)

가장 널리 쓰는 버전 관리 프로그램이에요. 내 컴퓨터에 설치해서 `git add`, `git commit` 같은 명령으로 폴더의 변경 기록을 저장해요. 인터넷이 없어도 동작하고, GitHub 같은 서비스와 연결하면 기록을 인터넷에도 올릴 수 있어요.

### GitHub
- 처음 등장: [P1 Day 7](#/day/p1-d07)

Git 저장소를 인터넷에 올려 두고 공유하는 웹 서비스예요(`https://github.com/`). 내 코드를 백업하고, 다른 사람과 함께 작업하고, GitHub Pages로 웹사이트를 공개할 수 있어요. Git은 내 컴퓨터의 프로그램이고, GitHub는 그 기록을 받아 주는 인터넷 서비스라는 점이 달라요.

### 저장소
- 처음 등장: [P1 Day 7](#/day/p1-d07)

Git이 변경 기록을 관리하는 프로젝트 폴더 하나예요. 영어로 repository, 줄여서 repo라고 해요. `git init`을 하면 그 폴더 안에 숨김 폴더 `.git`이 생기고, 그 안에 모든 기록이 쌓여요.

### 원격 저장소
- 처음 등장: [P1 Day 7](#/day/p1-d07)

내 컴퓨터가 아닌 인터넷(예: GitHub)에 있는 저장소예요. 내 컴퓨터의 저장소(로컬 저장소)와 연결해 두고, 커밋을 올리거나(푸시) 받아 와요. 이 교재에서는 `origin`이라는 이름으로 `https://github.com/<내 아이디>/my-creator-site` 저장소를 연결해요.

### 커밋
- 처음 등장: [P1 Day 7](#/day/p1-d07)

저장소의 지금 상태를 메시지와 함께 하나의 기록으로 남기는 것, 또는 그 기록 하나예요. `git commit -m "Day 8: 일정표"`처럼 무엇을 했는지 메시지를 붙여요. 커밋마다 고유 번호(해시)가 붙어서 나중에 그 시점으로 돌아가거나 비교할 수 있어요.

### 스테이징
- 처음 등장: [P1 Day 7](#/day/p1-d07)

다음 커밋에 넣을 변경을 골라 올려 두는 단계예요. `git add 파일`(전부면 `git add .`)로 하고, 올려 둔 변경만 커밋에 들어가요. 사진을 찍기 전에 찍을 물건을 상 위에 올려 두는 것과 비슷해요.

### 푸시
- 처음 등장: [P1 Day 7](#/day/p1-d07)

내 컴퓨터 저장소의 커밋을 원격 저장소로 올려 보내는 것이에요. `git push` 명령이나 VS Code 소스 제어 패널의 동기화 버튼으로 해요. 커밋만 하고 푸시하지 않으면 GitHub와 배포 사이트에는 바뀐 내용이 나타나지 않아요.

### 브랜치
- 처음 등장: [P1 Day 7](#/day/p1-d07)

저장소 안에서 커밋이 이어지는 하나의 줄기예요. 기본 줄기의 이름을 이 교재에서는 `main`으로 정하고, P1에서는 이 줄기 하나만 써요. 새 기능을 따로 실험할 때 줄기를 나누는 방법은 P2에서 배워요.

### 터미널
- 처음 등장: [P1 Day 7](#/day/p1-d07)

마우스 대신 글자로 명령을 입력해 컴퓨터를 다루는 창이에요. 명령을 한 줄 치고 `Enter`를 누르면 실행되고 결과가 글자로 나와요. 이 교재는 P1에서 VS Code 안의 터미널을 조금 쓰고, P2 Day 2에서 터미널 기초를 제대로 배워요.

### PowerShell
- 처음 등장: [P1 Day 7](#/day/p1-d07)

Windows에 들어 있는 터미널 프로그램이자 명령 언어예요. 터미널에 `PS C:\dev\my-creator-site>`처럼 `PS`로 시작하는 줄이 보이면 PowerShell이고, `>` 앞이 지금 위치예요. Windows 11에 기본으로 들어 있는 것은 Windows PowerShell 5.1이라서, 이 교재의 명령은 모두 이 버전에서 동작하게 썼어요.

## Day 8

### 표
- 처음 등장: [P1 Day 8](#/day/p1-d08)

줄(행)과 칸(열)으로 자료를 정리하는 HTML 요소 `table`이에요. 줄은 `tr`, 머리글 칸은 `th`, 내용 칸은 `td`로 만들고, 표 제목은 `caption`으로 달아요. 방송 일정처럼 줄과 칸이 있는 자료에만 쓰고, 화면 배치용으로는 쓰지 않아요.

### 폼
- 처음 등장: [P1 Day 8](#/day/p1-d08)

사용자가 글자를 입력하거나 고른 값을 모아 보내는 HTML 요소 `form`이에요. 안에 입력 칸(`input`), 고르기 상자(`select`), 여러 줄 입력(`textarea`), 보내기 버튼(`button`)을 넣어요. 보낸 값을 받아 처리하려면 서버가 필요해서, P1에서는 검사까지만 하고 실제 전송은 P2에서 해요.

### 레이블
- 처음 등장: [P1 Day 8](#/day/p1-d08)

입력 칸에 붙이는 이름표 요소 `label`이에요. `<label for="name">`의 `for` 값과 `<input id="name">`의 `id` 값을 같게 하면 둘이 연결돼서, 글자를 눌러도 칸에 커서가 들어가고 스크린 리더가 칸 이름을 읽어 줘요. 입력 칸마다 레이블을 하나씩 달아요.

### iframe
- 처음 등장: [P1 Day 8](#/day/p1-d08)

웹페이지 안에 다른 웹페이지를 창처럼 끼워 넣는 HTML 요소예요. 이름은 inline frame에서 왔어요. YouTube 영상을 내 페이지에 넣을 때 YouTube가 주는 `iframe` 코드를 써요. 화면 읽기 프로그램을 위해 `title` 속성으로 무엇을 담았는지 적어요.

### 임베드
- 처음 등장: [P1 Day 8](#/day/p1-d08)

다른 서비스의 콘텐츠(영상·지도·게시물)를 내 페이지 안에 넣어 보여 주는 것이에요. YouTube에서는 영상의 **공유 → 퍼가기**에서 임베드용 `iframe` 코드를 받아요. 영상 파일은 YouTube 서버에 그대로 있고, 내 페이지는 창만 빌려 보여 주는 방식이에요.

## Day 9

### CSS
- 처음 등장: [P1 Day 9](#/day/p1-d09)

웹페이지의 모양(색·글꼴·크기·여백·배치)을 정하는 언어예요. 이름은 Cascading Style Sheets의 머리글자예요. HTML이 "무엇이 있는지"를 적는다면 CSS는 "어떻게 보이는지"를 적고, 보통 `.css` 파일에 따로 써서 `<link>`로 여러 페이지에 함께 연결해요.

### 선택자
- 처음 등장: [P1 Day 9](#/day/p1-d09)

CSS 규칙을 어떤 요소에 적용할지 고르는 부분이에요. `body`처럼 요소 이름, `.site-header`처럼 점 뒤의 클래스 이름, `#greeting`처럼 `#` 뒤의 id로 골라요. JavaScript의 `querySelector`도 같은 선택자 문법으로 요소를 찾아요.

### 클래스
- 처음 등장: [P1 Day 9](#/day/p1-d09)

요소에 붙이는 이름표로, `class` 속성에 적어요. 같은 클래스를 여러 요소에 붙일 수 있고, 한 요소에 빈칸으로 나눠 여러 개(`class="button button-outline"`)를 붙일 수도 있어요. CSS에서는 앞에 점을 붙여 `.button`처럼 골라요.

### CSS 속성
- 처음 등장: [P1 Day 9](#/day/p1-d09)

CSS 규칙 안에서 바꿀 모양의 종류예요. `color: #1d1b2e;`의 `color`가 CSS 속성이고 `#1d1b2e`가 값이며, 끝에 세미콜론을 붙여요. HTML 태그 안의 속성(`class="…"`)과 이름은 같지만 다른 것이라, 교재에서는 "CSS 속성"이라고 구분해 불러요.

### 색상 코드
- 처음 등장: [P1 Day 9](#/day/p1-d09)

색을 `#` 뒤 여섯 글자로 적는 방법이에요. 앞에서부터 두 글자씩 빨강·초록·파랑의 세기를 `00`(없음)부터 `ff`(가장 셈)까지 16진수로 나타내요. `#ffffff`는 흰색, `#000000`은 검은색, `#5b4bdb`는 이 사이트의 보라색이에요.

### 캐시
- 처음 등장: [P1 Day 9](#/day/p1-d09)

한 번 받은 파일을 다시 받지 않으려고 브라우저가 잠시 보관해 두는 복사본이에요. 덕분에 페이지가 빨리 열리지만, 파일을 고쳤는데 화면이 그대로인 원인이 되기도 해요. 그럴 때는 `Ctrl + F5`(강력 새로 고침)로 캐시를 무시하고 다시 받아요.

## Day 10

### 박스 모델
- 처음 등장: [P1 Day 10](#/day/p1-d10)

브라우저가 모든 요소를 네모 상자로 보고 크기를 계산하는 방식이에요. 안쪽부터 내용, padding(안쪽 여백), border(테두리), margin(바깥 여백)의 네 겹으로 이뤄져요. 개발자 도구의 Computed(계산됨) 창에서 각 겹의 크기를 그림으로 볼 수 있어요.

### margin
- 처음 등장: [P1 Day 10](#/day/p1-d10)

상자의 테두리 바깥에 두는 여백으로, 다른 요소와의 거리를 정해요. `margin: 0 auto;`처럼 좌우를 `auto`로 두면 남는 공간을 양쪽이 나눠 가져서 상자가 가운데로 와요. 위아래로 붙은 두 상자의 margin은 더해지지 않고 큰 쪽 하나만 남기도 해요(마진 겹침).

### padding
- 처음 등장: [P1 Day 10](#/day/p1-d10)

상자의 내용과 테두리 사이의 안쪽 여백이에요. 배경색은 padding까지 칠해져서, 버튼이나 카드의 글자가 가장자리에 붙지 않게 할 때 써요. `padding: 0.5rem 1rem;`처럼 값을 둘 쓰면 위아래·좌우 순서예요.

### border
- 처음 등장: [P1 Day 10](#/day/p1-d10)

상자의 테두리 선이에요. `border: 1px solid #d9d6ee;`처럼 두께, 모양(`solid`는 실선), 색을 한 줄에 적어요. 모서리를 둥글게 하는 `border-radius`도 함께 쓰고, `50%`로 하면 정사각형 그림이 원이 돼요.

### box-sizing
- 처음 등장: [P1 Day 10](#/day/p1-d10)

`width`(폭)에 padding과 border를 포함할지 정하는 CSS 속성이에요. 기본값 `content-box`는 내용만 폭으로 쳐서 padding을 더하면 상자가 커지고, `border-box`는 테두리까지 포함해서 정한 폭이 그대로 유지돼요. 계산이 쉬워서 보통 `* { box-sizing: border-box; }`로 모든 요소에 적용해요.

### px
- 처음 등장: [P1 Day 10](#/day/p1-d10)

화면의 점 하나를 기준으로 한 CSS 길이 단위예요. `1px` 테두리처럼 정확히 고정된 크기가 필요할 때 써요. 사용자가 브라우저 글자 크기를 키워도 px로 정한 크기는 그대로라서, 글자 크기와 여백에는 보통 rem을 써요.

### rem
- 처음 등장: [P1 Day 10](#/day/p1-d10)

문서의 기본 글자 크기를 1로 보는 CSS 길이 단위예요. 기본 글자 크기가 16px이면 `1rem`은 16px, `1.5rem`은 24px이에요. 사용자가 글자 크기 설정을 키우면 rem으로 정한 크기도 함께 커져서 읽기 편한 사이트가 돼요.

## Day 11

### Flexbox
- 처음 등장: [P1 Day 11](#/day/p1-d11)

자식 요소들을 한 줄(가로 또는 세로)로 늘어놓고 정렬하는 CSS 배치 방법이에요. 부모에 `display: flex;`를 주면 시작되고, `gap`으로 간격, `justify-content`와 `align-items`로 정렬을 정해요. 메뉴 바, 버튼 묶음처럼 한 줄로 놓는 부품에 잘 맞아요.

### 주축
- 처음 등장: [P1 Day 11](#/day/p1-d11)

Flexbox에서 자식들이 늘어서는 방향이에요. 기본값은 가로(왼쪽 → 오른쪽)이고, `flex-direction: column;`으로 바꾸면 세로(위 → 아래)가 돼요. `justify-content`는 주축 방향의 정렬을 정해요.

### 교차축
- 처음 등장: [P1 Day 11](#/day/p1-d11)

Flexbox에서 주축과 직각인 방향이에요. 주축이 가로면 교차축은 세로예요. `align-items: center;`는 교차축 방향으로 가운데 정렬해서, 높이가 다른 로고 그림과 글자의 가운데를 맞춰 줘요.

### 속성 선택자
- 처음 등장: [P1 Day 11](#/day/p1-d11)

HTML 속성과 그 값으로 요소를 고르는 CSS 선택자예요. 대괄호를 써서 `a[aria-current="page"]`처럼 적으면 `aria-current` 값이 `page`인 링크만 골라요. JavaScript에서도 `querySelector('tr[data-day="1"]')`처럼 같은 모양으로 써요.

### ARIA
- 처음 등장: [P1 Day 11](#/day/p1-d11)

스크린 리더 같은 보조 기술에게 요소의 역할과 상태를 알려 주는 HTML 속성 묶음이에요. `aria-current="page"`(지금 페이지), `aria-expanded="true"`(펼쳐짐), `aria-pressed="true"`(눌림)처럼 `aria-`로 시작해요. 화면 모양은 바꾸지 않으므로, 모양은 CSS로 따로 맞춰요. 이름은 Accessible Rich Internet Applications의 머리글자예요.

## Day 12

### Grid
- 처음 등장: [P1 Day 12](#/day/p1-d12)

요소들을 줄과 칸이 있는 격자로 배치하는 CSS 방법이에요. 부모에 `display: grid;`를 주고 `grid-template-columns`로 칸의 개수와 폭을 정해요. 한 줄 정렬은 Flexbox, 카드 목록처럼 줄과 칸이 함께 있는 배치는 Grid가 잘 맞아요.

### fr
- 처음 등장: [P1 Day 12](#/day/p1-d12)

Grid에서 남는 공간을 나눠 갖는 몫을 나타내는 단위예요. `1fr 1fr`은 두 칸이 반씩, `200px 1fr`은 첫 칸 200px에 나머지를 둘째 칸이 모두 가져요. 이름은 fraction(몫)에서 왔어요.

### minmax
- 처음 등장: [P1 Day 12](#/day/p1-d12)

Grid 칸의 폭을 "최소 얼마부터 최대 얼마까지"로 정하는 함수예요. `minmax(240px, 1fr)`은 칸이 240px보다 좁아지지 않고, 공간이 남으면 똑같이 나눠 늘어난다는 뜻이에요. 카드가 너무 좁게 찌그러지지 않게 해 줘요.

### auto-fit
- 처음 등장: [P1 Day 12](#/day/p1-d12)

`repeat()` 안에 써서 "들어가는 만큼 칸을 만들어 줘"라고 정하는 값이에요. `repeat(auto-fit, minmax(240px, 1fr))`이면 화면이 넓으면 칸이 늘고 좁으면 줄어서, 미디어 쿼리 없이도 카드가 3칸·2칸·1칸으로 바뀌어요. 비슷한 `auto-fill`은 빈 칸 자리를 남기고, `auto-fit`은 있는 카드를 늘려 채워요.

## Day 13

### 반응형 웹
- 처음 등장: [P1 Day 13](#/day/p1-d13)

화면 폭에 맞춰 배치가 바뀌어서 휴대폰·태블릿·PC 어디서나 보기 좋은 웹사이트를 만드는 방식이에요. 같은 HTML에 미디어 쿼리 같은 CSS를 더해, 좁은 화면에서는 세로로 쌓고 넓은 화면에서는 나란히 놓아요. 요즘 시청자는 휴대폰으로 많이 보기 때문에 기본이 되었어요.

### 뷰포트
- 처음 등장: [P1 Day 13](#/day/p1-d13)

브라우저에서 웹페이지가 실제로 보이는 영역이에요. `<meta name="viewport" content="width=device-width, initial-scale=1">` 줄은 "뷰포트 폭을 기기 화면 폭에 맞춰요"라는 뜻이에요. 이 줄이 없으면 휴대폰이 PC용 화면을 작게 줄여서 보여 줘요.

### 미디어 쿼리
- 처음 등장: [P1 Day 13](#/day/p1-d13)

화면 조건에 따라 CSS 규칙을 켜고 끄는 문법이에요. `@media (min-width: 768px) { … }` 안의 규칙은 화면 폭이 768px 이상일 때만 적용돼요. 다크 모드 설정(`prefers-color-scheme`)이나 움직임 줄이기 설정처럼 화면 폭이 아닌 조건도 검사할 수 있어요.

### 모바일 우선
- 처음 등장: [P1 Day 13](#/day/p1-d13)

좁은 휴대폰 화면용 CSS를 기본으로 먼저 쓰고, 넓은 화면용은 미디어 쿼리로 덧붙이는 방식이에요. 그래서 미디어 쿼리에 `min-width`(이 폭 이상)를 써요. 작은 화면에서 꼭 필요한 것부터 생각하게 되고, 휴대폰이 쓸데없는 규칙을 덜 읽어요.

### 브레이크포인트
- 처음 등장: [P1 Day 13](#/day/p1-d13)

반응형 웹에서 배치가 바뀌는 화면 폭의 기준점이에요. 이 사이트는 768px을 브레이크포인트로 정해서, 그보다 넓으면 메뉴를 가로로 놓고 소개 영역을 2열로 바꿔요. 기기 이름이 아니라 "내용이 어색해지기 시작하는 폭"을 보고 정해요. 개발자 도구에서 코드를 멈추는 지점인 "중단점"과는 다른 말이에요.

## Day 14

### CSS 변수
- 처음 등장: [P1 Day 14](#/day/p1-d14)

CSS에서 값에 이름을 붙여 여러 곳에서 다시 쓰는 기능이에요. `:root { --accent: #5b4bdb; }`처럼 `--`로 시작하는 이름으로 정하고, `color: var(--accent);`처럼 꺼내 써요. 색을 한곳에서만 정해 두면 한 줄만 고쳐도 사이트 전체가 바뀌고, 다크 모드도 변수 값만 바꿔 만들어요.

### 의사 클래스
- 처음 등장: [P1 Day 14](#/day/p1-d14)

요소의 특별한 상태를 고르는 CSS 선택자예요. 콜론 하나를 붙여 `:hover`(마우스를 올렸을 때), `:focus`(입력 중일 때), `:focus-visible`(키보드로 고른 때), `:empty`(내용이 비었을 때)처럼 써요. HTML에 클래스를 붙이지 않아도 상태에 따라 모양을 바꿀 수 있어요.

### 트랜지션
- 처음 등장: [P1 Day 14](#/day/p1-d14)

CSS 값이 바뀔 때 한순간에 바뀌지 않고 정한 시간 동안 부드럽게 바뀌게 하는 기능이에요. `transition: transform 0.15s;`처럼 바뀔 CSS 속성과 걸리는 시간을 적어요. 버튼이 살짝 떠오르거나 다크 모드로 바뀔 때 자연스럽게 보이게 해 줘요.

### 배포
- 처음 등장: [P1 Day 14](#/day/p1-d14)

내 컴퓨터에서 만든 프로그램이나 웹사이트를 서버에 올려, 다른 사람이 인터넷으로 쓸 수 있게 하는 일이에요. P1에서는 GitHub Pages에 올려 `https://` 주소를 받아요. 배포한 뒤에도 고친 내용을 다시 올리면 사이트가 새 모습으로 바뀌어요.

### GitHub Pages
- 처음 등장: [P1 Day 14](#/day/p1-d14)

GitHub 저장소의 HTML·CSS·JS 파일을 그대로 웹사이트로 공개해 주는 GitHub의 무료 기능이에요. 저장소 **Settings → Pages**에서 브랜치를 고르면 `https://<아이디>.github.io/<저장소 이름>/` 주소가 생겨요. 무료 계정은 공개(Public) 저장소에서만 쓸 수 있고, 서버 프로그램은 돌릴 수 없어요.

## Day 15

### JavaScript
- 처음 등장: [P1 Day 15](#/day/p1-d15)

웹페이지가 움직이고 반응하게 만드는 프로그래밍 언어예요. 브라우저 안에서 실행되어 버튼을 누르면 메뉴를 열고, 데이터를 읽어 화면에 그리고, 시간을 계산해요. 보통 `.js` 파일에 써서 `<script>`로 HTML에 연결해요. 이름은 비슷해도 Java라는 언어와는 다른 언어예요.

### 콘솔
- 처음 등장: [P1 Day 15](#/day/p1-d15)

개발자 도구의 Console(콘솔) 창이에요. `console.log()`로 출력한 값과 JavaScript 오류 메시지가 여기에 나오고, 맨 아래 칸에 코드를 직접 쳐서 바로 실행해 볼 수도 있어요. 빨간 글자는 오류, 노란 글자는 경고예요.

### 변수
- 처음 등장: [P1 Day 15](#/day/p1-d15)

값에 이름을 붙여 담아 두는 상자예요. `const siteName = '달빛곰 방송국';`처럼 만들고, 그다음부터는 이름으로 그 값을 꺼내 써요. 나중에 값을 바꿀 상자는 `let`, 바꾸지 않을 상자는 `const`로 만들어요.

### 자료형
- 처음 등장: [P1 Day 15](#/day/p1-d15)

값의 종류예요. JavaScript에는 문자열(`'안녕'`), 숫자(`20`), 불리언(`true`), `undefined`, `null`, 그리고 나중에 배울 배열·객체 등이 있어요. 종류에 따라 쓸 수 있는 연산이 달라서, `'20' + 1`은 글자를 이어 붙여 `'201'`이 되고 `20 + 1`은 `21`이 돼요. `typeof 값`으로 종류를 확인해요.

### 문자열
- 처음 등장: [P1 Day 15](#/day/p1-d15)

따옴표로 감싼 글자 값이에요. 이 교재의 JavaScript는 작은따옴표(`'달빛곰'`)를 쓰고, 값을 끼워 넣을 때는 백틱(`` ` ``)을 써요(템플릿 리터럴). 문자열끼리 `+`를 하면 이어 붙여지고, `.length`로 글자 수를 알 수 있어요.

### 불리언
- 처음 등장: [P1 Day 15](#/day/p1-d15)

참(`true`)과 거짓(`false`) 둘 중 하나만 갖는 값이에요. `20 > 15`처럼 비교한 결과가 불리언이고, `if` 조건문은 이 값에 따라 실행할 코드를 골라요. 메뉴가 열렸는지 같은 켜짐·꺼짐 상태를 담을 때도 써요.

### undefined
- 처음 등장: [P1 Day 15](#/day/p1-d15)

"아직 값이 정해지지 않았어요"라는 뜻의 JavaScript 값이에요. `let message;`처럼 값을 넣지 않은 변수, 배열에 없는 칸(`days[10]`), `return`이 없는 함수의 결과가 `undefined`예요. 화면에 `undefined`가 보이면 이름 오타나 빠진 값을 의심해요.

### null
- 처음 등장: [P1 Day 15](#/day/p1-d15)

"일부러 비워 두었어요"라는 뜻의 JavaScript 값이에요. `document.querySelector()`가 찾는 요소가 없을 때, `localStorage.getItem()`에 저장된 값이 없을 때 `null`을 돌려줘요. `null`인 값에서 속성을 꺼내려 하면 `Cannot read properties of null` 오류가 나요.

### 연산자
- 처음 등장: [P1 Day 15](#/day/p1-d15)

값을 계산하거나 비교하는 기호예요. `+ - * /`는 사칙 연산, `%`는 나눈 나머지(`10 % 3`은 `1`), `=`는 변수에 값을 넣기예요. 같은지 비교하는 `===`, 그리고 `&&`·`||` 같은 논리 연산자는 Day 16에서 배워요.

### NaN
- 처음 등장: [P1 Day 15](#/day/p1-d15)

"숫자가 아니에요(Not a Number)"라는 뜻의 특별한 숫자 값이에요. `Number('스물')`처럼 숫자로 바꿀 수 없는 글자를 바꾸거나 계산이 잘못되면 나와요. `NaN`은 어떤 값과 비교해도(`NaN >= 0`도, `NaN <= 23`도) 거짓이라서, 잘못 입력된 값을 걸러 내는 데 쓸 수 있어요.

### defer
- 처음 등장: [P1 Day 15](#/day/p1-d15)

`<script src="js/main.js" defer>`처럼 쓰는 속성으로, "HTML을 끝까지 읽은 다음에 이 스크립트를 실행해 줘요"라는 뜻이에요. 그래서 `head` 안에 두어도 스크립트가 찾는 요소가 이미 만들어져 있어요. `defer`가 없으면 아직 없는 요소를 찾다가 `null` 오류가 날 수 있어요.

## Day 16

### 조건문
- 처음 등장: [P1 Day 16](#/day/p1-d16)

조건이 참인지 거짓인지에 따라 다른 코드를 실행하게 하는 문법이에요. `if (조건) { … } else if (다른 조건) { … } else { … }`처럼 위에서부터 차례로 검사해서 처음 참인 블록 하나만 실행해요. 시간대에 따라 다른 인사말을 고를 때 써요.

### 비교 연산자
- 처음 등장: [P1 Day 16](#/day/p1-d16)

두 값을 비교해서 참이나 거짓을 돌려주는 연산자예요. `===`(같다), `!==`(다르다), `<`, `<=`, `>`, `>=`가 있어요. `==`는 종류가 다른 값을 멋대로 바꿔 비교하기 때문에, 이 교재는 종류까지 같아야 참인 `===`만 써요.

### 논리 연산자
- 처음 등장: [P1 Day 16](#/day/p1-d16)

여러 조건을 묶거나 뒤집는 연산자예요. `&&`는 둘 다 참일 때, `||`는 하나라도 참일 때 참이고, `!`는 참과 거짓을 뒤집어요. `||`는 `params.get('title') || '방송 시작까지'`처럼 "앞 값이 비었으면 뒤 값을 써요"라는 기본값 용도로도 써요.

### 템플릿 리터럴
- 처음 등장: [P1 Day 16](#/day/p1-d16)

백틱(`` ` ``)으로 감싸서 안에 `${ }`로 값을 끼워 넣는 문자열이에요. `` `영상 ${count}개` ``처럼 쓰면 `count` 값이 그 자리에 들어가요. `+`로 이어 붙이는 것보다 읽기 쉬워요. 백틱은 키보드 숫자 `1` 왼쪽 키이고, 영어 입력 상태에서 쳐요.

### 삼항 연산자
- 처음 등장: [P1 Day 16](#/day/p1-d16)

`조건 ? 참일 때 값 : 거짓일 때 값` 모양으로, 조건에 따라 두 값 중 하나를 고르는 연산자예요. `hour < 12 ? '오전' : '오후'`는 12시 전이면 `'오전'`, 아니면 `'오후'`가 돼요. 짧은 if/else를 한 줄로 쓸 때 편해요.

### Date
- 처음 등장: [P1 Day 16](#/day/p1-d16)

날짜와 시각을 다루는 JavaScript 기능이에요. `new Date()`는 지금 시각을 담은 객체를 만들고, `.getHours()`(0~23시), `.getDay()`(일요일 0 ~ 토요일 6) 같은 메서드로 값을 꺼내요. 컴퓨터 시계를 기준으로 계산하므로, 한국에서 쓰는 컴퓨터면 한국 시간이 나와요.

## Day 17

### 배열
- 처음 등장: [P1 Day 17](#/day/p1-d17)

여러 값을 순서대로 한 줄에 담는 자료형이에요. `const days = ['월', '수', '금', '토'];`처럼 대괄호와 쉼표로 만들고, `days.length`로 개수를 알아요. `push()`로 끝에 값을 더할 수 있고, 반복문으로 하나씩 꺼내 써요.

### 인덱스
- 처음 등장: [P1 Day 17](#/day/p1-d17)

배열 안에서 값의 자리를 나타내는 번호예요. 0부터 세기 때문에 `days[0]`이 첫 번째, `days[3]`이 네 번째 값이에요. 마지막 인덱스는 `length - 1`이고, 없는 자리를 꺼내면 `undefined`가 나와요.

### 반복문
- 처음 등장: [P1 Day 17](#/day/p1-d17)

같은 코드를 여러 번 되풀이해 실행하는 문법이에요. `for (let i = 0; i < 4; i++) { … }`는 `i`가 0, 1, 2, 3일 때 네 번 실행돼요. 끝나는 조건이 영영 참이 되지 않으면 무한 반복이 되어 브라우저 탭이 멈추니 조심해요.

### for...of
- 처음 등장: [P1 Day 17](#/day/p1-d17)

배열의 값을 처음부터 하나씩 꺼내 반복하는 문법이에요. `for (const day of days) { console.log(day); }`처럼 쓰면 인덱스를 세지 않아도 돼요. 비슷하게 생긴 `for...in`은 값이 아니라 자리 번호를 꺼내므로 배열에는 `for...of`를 써요.

## Day 18

### 함수
- 처음 등장: [P1 Day 18](#/day/p1-d18)

여러 줄의 코드를 하나로 묶고 이름을 붙여, 필요할 때 불러 쓰는 것이에요. `function pad(number) { … }`처럼 만들고 `pad(5)`처럼 이름 뒤에 괄호를 붙여 호출해요. 같은 코드를 되풀이해 쓰지 않게 해 주고, 이름만 봐도 무슨 일을 하는지 알 수 있게 해요.

### 매개변수
- 처음 등장: [P1 Day 18](#/day/p1-d18)

함수를 부를 때 넘겨받는 값을 담는 변수예요. `function makeGreeting(name) { … }`의 `name`이 매개변수이고, `makeGreeting('달빛곰')`처럼 부를 때 넘긴 `'달빛곰'`(인수)이 그 안에 들어가요. 매개변수는 그 함수 안에서만 쓸 수 있어요.

### 반환값
- 처음 등장: [P1 Day 18](#/day/p1-d18)

함수가 일을 마치고 부른 쪽에 돌려주는 결과예요. 함수 안에서 `return 값;`으로 돌려주고, `const text = pad(5);`처럼 받아서 써요. `return`을 만나면 함수는 그 자리에서 끝나고, `return`이 없으면 반환값은 `undefined`예요.

### 화살표 함수
- 처음 등장: [P1 Day 18](#/day/p1-d18)

`=>` 기호로 짧게 쓰는 함수예요. `const double = (n) => n * 2;`처럼 쓰면 `n * 2`가 바로 반환값이 되고, 중괄호를 쓰면 `return`을 직접 적어야 해요. 다른 함수에 넘기는 콜백(`forEach`, `addEventListener` 등)에 주로 써요.

### 스코프
- 처음 등장: [P1 Day 18](#/day/p1-d18)

변수를 쓸 수 있는 범위예요. `let`·`const`로 만든 변수는 그 변수를 만든 중괄호 `{ }` 블록 안에서만 쓸 수 있고, 밖에서 쓰면 `ReferenceError`가 나요. 바깥에서 만든 변수는 안쪽 블록과 함수에서도 쓸 수 있어요.

## Day 19

### 객체
- 처음 등장: [P1 Day 19](#/day/p1-d19)

이름(키)과 값을 짝지어 여러 정보를 한 덩어리로 담는 자료형이에요. `{ title: '신청곡 라이브', category: 'music' }`처럼 중괄호 안에 `키: 값`을 쉼표로 이어 적어요. 영상 하나, 방송 일정 하나처럼 여러 정보를 가진 대상을 표현할 때 써요.

### 키
- 처음 등장: [P1 Day 19](#/day/p1-d19)

객체 안에서 값을 찾는 이름이에요. `video.title`처럼 점 뒤에 키를 쓰거나, `categoryNames[video.category]`처럼 대괄호 안에 키(또는 키가 든 변수)를 넣어 값을 꺼내요. `localStorage`에 저장할 때 붙이는 이름(`'theme'`)도 키라고 불러요.

### 메서드
- 처음 등장: [P1 Day 19](#/day/p1-d19)

객체에 딸린 함수예요. `console.log()`는 `console` 객체의 `log` 메서드이고, `days.push('일')`은 배열의 `push` 메서드예요. 값 뒤에 점과 메서드 이름, 괄호를 붙여 불러요.

### 콜백 함수
- 처음 등장: [P1 Day 19](#/day/p1-d19)

다른 함수에 값처럼 넘겨서, 그 함수가 알맞은 때에 대신 불러 주는 함수예요. `videos.forEach((video) => { … })`에서 화살표 함수가 콜백이고, `forEach`가 영상마다 한 번씩 불러 줘요. 버튼을 누를 때 실행할 코드를 `addEventListener`에 넘기는 것도 콜백이에요.

### 배열 메서드
- 처음 등장: [P1 Day 19](#/day/p1-d19)

배열이 기본으로 갖고 있는 메서드들이에요. `forEach`는 값마다 콜백을 실행하고, `map`은 콜백의 결과로 새 배열을 만들고, `filter`는 콜백이 참을 돌려준 값만 모아 새 배열을 만들어요. `map`과 `filter`는 원래 배열을 바꾸지 않아요.

## Day 20

### DOM
- 처음 등장: [P1 Day 20](#/day/p1-d20)

브라우저가 HTML을 읽어 만든, 요소들이 나무처럼 이어진 구조예요. 이름은 Document Object Model의 머리글자예요. JavaScript는 `document`에서 시작해 이 나무의 요소를 찾고, 글자를 바꾸고, 새 요소를 붙여 화면을 바꿔요. 개발자 도구 Elements 창에 보이는 것이 지금의 DOM이에요.

### querySelector
- 처음 등장: [P1 Day 20](#/day/p1-d20)

CSS 선택자로 요소를 하나 찾아 주는 메서드예요. `document.querySelector('#video-list')`처럼 쓰고, 조건에 맞는 첫 요소를 돌려주며 없으면 `null`을 돌려줘요. 맞는 요소를 모두 찾으려면 `querySelectorAll`을 써요.

### textContent
- 처음 등장: [P1 Day 20](#/day/p1-d20)

요소 안의 글자를 읽거나 바꾸는 속성이에요. `title.textContent = video.title;`처럼 넣으면 꺾쇠까지 모두 글자 그대로 보여서, 남이 쓴 글을 넣어도 태그로 실행되지 않아 안전해요. `textContent = ''`으로 요소 안을 비울 수도 있어요.

### classList
- 처음 등장: [P1 Day 20](#/day/p1-d20)

요소의 클래스 목록을 다루는 속성이에요. `classList.add('today')`로 붙이고, `remove`로 떼고, `contains`로 붙어 있는지 묻고, `toggle`로 있으면 떼고 없으면 붙여요. JavaScript가 클래스를 바꾸면 CSS에 미리 써 둔 모양이 적용돼요.

### createElement
- 처음 등장: [P1 Day 20](#/day/p1-d20)

새 HTML 요소를 JavaScript로 만드는 메서드예요. `document.createElement('article')`로 만든 요소는 아직 화면에 없고, 속성과 글자를 넣은 뒤 `appendChild()`로 화면에 있는 요소 안에 붙여야 보여요. 데이터 개수만큼 카드를 만들 때 써요.

## Day 21

### 이벤트
- 처음 등장: [P1 Day 21](#/day/p1-d21)

웹페이지에서 일어나는 일이에요. 버튼 클릭(`click`), 글자 입력(`input`), 폼 보내기(`submit`) 등이 있어요. JavaScript는 이벤트가 일어날 때 실행할 코드를 미리 정해 둬서 사용자의 행동에 반응해요.

### 이벤트 리스너
- 처음 등장: [P1 Day 21](#/day/p1-d21)

특정 요소에서 이벤트가 일어나기를 기다렸다가 실행되는 함수예요. `button.addEventListener('click', () => { … });`처럼 이벤트 이름과 실행할 콜백을 넘겨 달아요. 콜백은 `event` 객체를 받아서, `event.target`으로 실제로 누른 요소를 알 수 있어요.

### 이벤트 위임
- 처음 등장: [P1 Day 21](#/day/p1-d21)

여러 자식 요소에 각각 리스너를 달지 않고, 감싸는 부모 하나에만 달아 처리하는 방법이에요. 자식에서 일어난 이벤트가 부모까지 전해지는 성질을 이용하고, `event.target.closest('button')`으로 어느 버튼을 눌렀는지 찾아요. 버튼이 늘어나거나 나중에 만들어져도 리스너 하나로 충분해요.

### 햄버거 메뉴
- 처음 등장: [P1 Day 21](#/day/p1-d21)

좁은 화면에서 메뉴를 숨겨 두고, 버튼을 누르면 펼쳐 보여 주는 메뉴 방식이에요. 버튼의 `☰` 모양이 햄버거를 닮아서 이렇게 불러요. 열렸는지는 `aria-expanded`로 스크린 리더에게도 알려 줘요.

### data 속성
- 처음 등장: [P1 Day 21](#/day/p1-d21)

`data-`로 시작하는 이름으로 HTML 요소에 내 데이터를 붙여 두는 속성이에요. `<button data-category="game">`처럼 쓰고, JavaScript에서는 `button.dataset.category`로 `'game'`을 읽어요. 화면에는 보이지 않지만 JavaScript와 CSS가 그 값을 쓸 수 있어요.

## Day 22

### 다크 모드
- 처음 등장: [P1 Day 22](#/day/p1-d22)

어두운 배경에 밝은 글자로 화면을 보여 주는 색 구성이에요. 밤에 눈이 덜 부시고, Windows·휴대폰에도 설정이 있어요. 이 사이트는 `<html>`에 `data-theme="dark"`가 붙으면 CSS 변수 값만 어두운 색으로 바꾸는 방식으로 만들어요.

### localStorage
- 처음 등장: [P1 Day 22](#/day/p1-d22)

브라우저 안에 키와 값을 저장해 두는 작은 저장소예요. `localStorage.setItem('theme', 'dark')`로 저장하고 `getItem('theme')`으로 꺼내며, 창을 닫았다 열어도 남아 있어요. 글자만 저장되고, 브라우저마다 그리고 사이트 주소마다 따로 저장돼요.

### prefers-color-scheme
- 처음 등장: [P1 Day 22](#/day/p1-d22)

사용자가 컴퓨터나 휴대폰에서 다크 모드를 켰는지 알려 주는 미디어 쿼리 조건이에요. CSS에서는 `@media (prefers-color-scheme: dark)`, JavaScript에서는 `window.matchMedia('(prefers-color-scheme: dark)').matches`로 확인해요. 이 사이트는 사용자가 직접 고른 적이 없을 때 이 설정을 따라가요.

## Day 23

### input 이벤트
- 처음 등장: [P1 Day 23](#/day/p1-d23)

입력 칸의 값이 바뀔 때마다 일어나는 이벤트예요. 글자를 하나 칠 때마다, 지울 때마다 일어나서 검색어를 바로바로 반영할 수 있어요. 한글은 글자를 조합하는 중에도 일어나서, 다 치기 전의 글자로 잠깐 걸러지는 것이 정상이에요.

### hidden 속성
- 처음 등장: [P1 Day 23](#/day/p1-d23)

요소를 화면에서 숨기는 HTML 속성이에요. `<p id="empty-message" hidden>`처럼 쓰면 보이지 않고, JavaScript에서 `element.hidden = false;`로 다시 보여 줄 수 있어요. CSS의 다른 `display` 규칙에 지지 않게 `[hidden] { display: none !important; }`를 함께 둬요.

### 문자열 메서드
- 처음 등장: [P1 Day 23](#/day/p1-d23)

문자열이 기본으로 갖고 있는 메서드들이에요. `trim()`은 앞뒤 빈칸을 지우고, `toLowerCase()`는 영어를 소문자로 바꾸고, `includes('기타')`는 그 글자가 들어 있는지 참·거짓으로 알려 줘요. `split(':')`은 기호를 기준으로 잘라 배열을 만들어요(Day 26). 원래 문자열은 바뀌지 않고 새 결과를 돌려줘요.

## Day 24

### 폼 검증
- 처음 등장: [P1 Day 24](#/day/p1-d24)

폼에 입력한 값이 규칙에 맞는지 보내기 전에 검사하고, 틀린 곳을 알려 주는 일이에요. HTML 속성(`required`, `type="email"`, `pattern`)과 JavaScript 검사를 함께 써요. 브라우저의 검사는 사용자를 돕는 것이고, 진짜 서비스에서는 서버도 다시 검사해야 해요(P2).

### 정규 표현식
- 처음 등장: [P1 Day 24](#/day/p1-d24)

글자의 모양 규칙을 기호로 적은 검사식이에요. `[A-Za-z0-9가-힣_]{2,20}`은 "영어·숫자·완성된 한글·밑줄로 된 2~20글자"라는 뜻이고, JavaScript에서는 `/^…$/` 모양으로 써서 `.test(값)`으로 맞는지 확인해요. 짧지만 읽기 어려우니 한 조각씩 뜻을 확인하며 써요.

### 제약 조건 검증 API
- 처음 등장: [P1 Day 24](#/day/p1-d24)

HTML 입력 칸의 검사 결과를 JavaScript에서 읽을 수 있게 해 주는 브라우저 기능이에요(Constraint Validation API). 입력 칸의 `validity` 객체에 결과가 들어 있어서, 예를 들어 `input.validity.patternMismatch`는 값이 `pattern` 규칙과 다르면 `true`예요. HTML에 적은 규칙을 JavaScript에서 다시 쓰지 않아도 돼요.

### preventDefault
- 처음 등장: [P1 Day 24](#/day/p1-d24)

이벤트에 붙은 브라우저의 기본 동작을 막는 메서드예요. 폼의 `submit` 이벤트에서 `event.preventDefault();`를 부르면 페이지가 새로 고침되며 값을 주소에 붙여 보내는 기본 동작이 멈춰요. 그 대신 JavaScript로 검사하고 안내 문장을 보여 줄 수 있어요.

### aria-live
- 처음 등장: [P1 Day 24](#/day/p1-d24)

"이 영역의 글자가 바뀌면 읽어 주세요"라고 스크린 리더에게 알리는 ARIA 속성이에요. `aria-live="polite"`는 하던 말을 마친 뒤 알려 주고, `role="status"`도 같은 뜻이에요. 화면을 보지 못해도 "고칠 곳이 3군데 있어요", "영상 2개" 같은 변화를 알 수 있게 해요.

## Day 25

### JSON
- 처음 등장: [P1 Day 25](#/day/p1-d25)

데이터를 글자로 주고받기 위한 형식이에요. 이름은 JavaScript Object Notation이고, 객체·배열과 비슷하게 생겼지만 키와 문자열은 반드시 큰따옴표로 쓰고, 마지막 쉼표와 주석은 쓸 수 없어요. 이 사이트는 영상 목록과 방송 일정을 `.json` 파일로 따로 두고 읽어 와요.

### fetch
- 처음 등장: [P1 Day 25](#/day/p1-d25)

JavaScript로 서버에 파일이나 데이터를 요청해 받아 오는 브라우저 기능이에요. `fetch('data/videos.json')`처럼 주소를 넘기고, 결과가 오기까지 시간이 걸리므로 `await`로 기다려요. 보안 때문에 파일을 더블클릭해 연 페이지(`file://`)에서는 동작하지 않아서 Live Preview나 배포 주소로 열어요.

### 비동기
- 처음 등장: [P1 Day 25](#/day/p1-d25)

시간이 걸리는 일을 시켜 놓고 끝날 때까지 멈춰 있지 않고, 결과가 오면 이어서 처리하는 방식이에요. 파일을 받아 오는 동안에도 버튼과 검색창이 계속 반응하는 것이 비동기 덕분이에요. JavaScript에서는 `async` 함수와 `await`로 비동기 코드를 위에서 아래로 읽히게 써요.

### async 함수
- 처음 등장: [P1 Day 25](#/day/p1-d25)

`async function loadVideos() { … }`처럼 앞에 `async`를 붙인 함수예요. 이 함수 안에서만 `await`를 쓸 수 있고, 함수는 시간이 걸리는 일을 기다리는 동안 다른 코드가 먼저 실행되게 비켜 줘요. 파일을 불러와 화면을 그리는 일처럼 기다림이 있는 작업을 담아요.

### await
- 처음 등장: [P1 Day 25](#/day/p1-d25)

`async` 함수 안에서 "결과가 올 때까지 기다렸다가 다음 줄로 가요"라는 뜻으로 쓰는 낱말이에요. `const response = await fetch('data/videos.json');`처럼 쓰면 받아 온 결과가 변수에 들어가요. `async`가 없는 함수 안에서 쓰면 오류가 나요.

### try...catch
- 처음 등장: [P1 Day 25](#/day/p1-d25)

오류가 날 수 있는 코드를 `try { … }`에 넣고, 오류가 나면 `catch (error) { … }`에서 대신 처리하는 문법이에요. 오류가 나도 사이트 전체가 멈추지 않고 "불러오지 못했어요" 같은 안내를 보여 줄 수 있어요. `throw new Error('…')`로 일부러 오류를 던져 `catch`로 보낼 수도 있어요.

## Day 26

### setInterval
- 처음 등장: [P1 Day 26](#/day/p1-d26)

함수를 정한 시간마다 되풀이해 실행하는 브라우저 기능이에요. `setInterval(updateCountdown, 1000)`은 1000밀리초(1초)마다 `updateCountdown`을 불러요. 함수 이름 뒤에 괄호를 붙이지 않고 넘기며, 돌려받은 번호를 `clearInterval(번호)`에 넘기면 멈춰요(Day 27).

### 밀리초
- 처음 등장: [P1 Day 26](#/day/p1-d26)

1초를 1000으로 나눈 시간 단위예요(ms). JavaScript는 시간을 밀리초로 계산해서, `setInterval`의 `1000`은 1초이고, Date끼리 빼면 두 시각의 차이가 밀리초 숫자로 나와요. 초로 바꾸려면 1000으로 나누고 `Math.floor`로 소수를 버려요.

### 의사 요소
- 처음 등장: [P1 Day 26](#/day/p1-d26)

HTML에 없는 가상의 요소를 CSS로 만들어 꾸미는 선택자예요. 콜론 두 개를 써서 `::after`(요소 내용의 뒤), `::before`(앞)처럼 적고, `content: " (오늘)";`로 넣을 글자를 정해요. 이 사이트는 오늘 요일 행에 색과 함께 `(오늘)` 글자를 붙여, 색을 구별하기 어려운 사람도 알 수 있게 해요.

## Day 27

### 오버레이
- 처음 등장: [P1 Day 27](#/day/p1-d27)

방송 화면 위에 한 겹 겹쳐서 보여 주는 그림이나 글자예요. 카운트다운, 후원 알림, 채팅창 등이 대표적이에요. 배경이 투명한 웹페이지로 만들면 게임 화면 위에 글자만 떠 보여요.

### OBS Studio
- 처음 등장: [P1 Day 27](#/day/p1-d27)

방송과 녹화에 널리 쓰는 무료 프로그램이에요(`https://obsproject.com/`). 게임 화면·카메라·웹페이지 같은 여러 소스를 한 화면에 겹쳐 방송 플랫폼으로 내보내요. 이 교재는 작성 기준 33.0.1 버전을 기준으로 설명하고, 메뉴 이름은 버전에 따라 조금 다를 수 있어요.

### 브라우저 소스
- 처음 등장: [P1 Day 27](#/day/p1-d27)

OBS Studio에서 웹페이지를 방송 화면의 한 겹으로 띄우는 소스 종류예요. 속성 창의 URL 칸에 주소를 넣고 너비와 높이를 정하면, OBS 안의 브라우저가 그 페이지를 그려요. 페이지 배경이 투명하면 아래 겹(게임 화면)이 그대로 비쳐 보여요.

### URL 파라미터
- 처음 등장: [P1 Day 27](#/day/p1-d27)

주소 끝에 `?` 다음으로 붙여 페이지에 값을 넘기는 부분이에요. `countdown.html?title=저녁 방송&start=20:00`처럼 `이름=값`을 `&`로 이어 적어요. 같은 페이지 파일 하나로 주소만 바꿔 서로 다른 방송 제목과 시각을 보여 줄 수 있어요. 쿼리 문자열이라고도 불러요.

### URLSearchParams
- 처음 등장: [P1 Day 27](#/day/p1-d27)

URL 파라미터를 쉽게 읽게 해 주는 JavaScript 기능이에요. `new URLSearchParams(location.search)`로 만들고 `.get('title')`로 값을 꺼내며, 그 이름이 없으면 `null`을 돌려줘요. `%20` 같은 인코딩된 글자도 원래 글자로 풀어 줘요.

### vw
- 처음 등장: [P1 Day 27](#/day/p1-d27)

뷰포트 폭을 100으로 보는 CSS 길이 단위예요. `6vw`는 화면 폭의 6%이고, 높이를 기준으로 하는 `vh`도 있어요(`100vh` = 화면 높이 전체). OBS 브라우저 소스의 크기를 바꿔도 글자가 비율에 맞게 커지고 작아지게 할 때 써요.

### clamp
- 처음 등장: [P1 Day 27](#/day/p1-d27)

CSS 값을 최솟값과 최댓값 사이로 묶어 주는 함수예요. `clamp(1.25rem, 6vw, 2.5rem)`은 보통은 화면 폭의 6%를 쓰되, 1.25rem보다 작아지거나 2.5rem보다 커지지는 않게 해요. 미디어 쿼리 없이도 화면 크기에 맞는 글자 크기를 만들 수 있어요.

## Day 28

### 건너뛰기 링크
- 처음 등장: [P1 Day 28](#/day/p1-d28)

페이지 맨 앞에 두는 "본문 바로가기" 링크예요. 평소에는 화면 밖에 숨어 있다가 키보드로 `Tab`을 처음 누르면 나타나서, 매번 메뉴를 하나하나 지나지 않고 바로 본문(`#main`)으로 가게 해 줘요. 키보드나 스크린 리더로 사이트를 쓰는 사람을 위한 접근성 기능이에요.

### SEO
- 처음 등장: [P1 Day 28](#/day/p1-d28)

검색 엔진이 내 페이지를 잘 이해하고 검색 결과에 알맞게 보여 주도록 다듬는 일이에요. 이름은 Search Engine Optimization의 머리글자예요. 페이지마다 다른 `<title>`, 내용을 요약한 `<meta name="description">`, 의미에 맞는 제목 구조가 기본이에요.

### Open Graph
- 처음 등장: [P1 Day 28](#/day/p1-d28)

링크를 메신저나 SNS에 공유할 때 보이는 미리 보기(제목·설명·그림)를 정하는 `meta` 태그 규칙이에요. `<meta property="og:title" content="…">`처럼 `og:`로 시작하는 이름을 써요. 그림(`og:image`)은 `https://`로 시작하는 전체 주소가 필요해서 배포 주소가 정해진 뒤에 넣어요.

### 파비콘
- 처음 등장: [P1 Day 28](#/day/p1-d28)

브라우저 탭과 즐겨찾기에 보이는 사이트의 작은 아이콘이에요. `<link rel="icon" href="favicon.svg" type="image/svg+xml">`로 연결해요. 브라우저가 아이콘을 오래 기억하므로, 바꿨는데 그대로면 새 탭으로 열거나 강력 새로 고침을 해요.

### 지연 로딩
- 처음 등장: [P1 Day 28](#/day/p1-d28)

화면에 보이지 않는 그림이나 iframe은 미리 받지 않고, 스크롤해서 가까워질 때 받는 방식이에요. `<img loading="lazy">`나 `<iframe loading="lazy">`처럼 속성 하나로 켜요. 처음 열 때 받을 양이 줄어 페이지가 빨리 보여요.

### Lighthouse
- 처음 등장: [P1 Day 28](#/day/p1-d28)

Chrome 개발자 도구에 들어 있는 웹페이지 품질 검사 도구예요. 성능, 접근성, 권장 사항, SEO를 검사해 점수와 고칠 점 목록을 보여 줘요. 확장 프로그램과 네트워크 상태에 따라 점수가 매번 조금씩 달라서, 시크릿 창에서 배포 주소로 검사하는 것이 좋아요.

## Day 29

### 버그
- 처음 등장: [P1 Day 29](#/day/p1-d29)

프로그램이 만든 사람의 뜻과 다르게 동작하는 잘못이에요. 오류 메시지가 나는 버그도 있고, 오류 없이 결과만 틀리는 버그도 있어요. 버그를 찾아 고치는 일을 디버깅이라고 해요.

### 디버깅
- 처음 등장: [P1 Day 29](#/day/p1-d29)

버그의 원인을 찾아 고치는 과정이에요. 다시 일어나게 하기 → 오류 원문 읽기 → 위치 찾기 → 원인 짐작 → 고치고 확인하기 순서로 해요. `console.log`로 값을 찍어 보거나 개발자 도구의 중단점으로 코드를 멈춰 살펴봐요.

### 중단점
- 처음 등장: [P1 Day 29](#/day/p1-d29)

코드가 그 줄에 오면 실행을 잠시 멈추게 하는 표시예요(breakpoint). 개발자 도구 Sources 창에서 줄 번호를 누르면 걸리고, 멈춘 동안 변수 값을 보거나 한 줄씩 실행해 볼 수 있어요. 다 쓰면 줄 번호를 다시 눌러 해제해요. CSS의 "브레이크포인트"(배치가 바뀌는 화면 폭)와는 다른 말이에요.

### Markdown
- 처음 등장: [P1 Day 29](#/day/p1-d29)

`#`, `-`, `` ` `` 같은 간단한 기호로 제목·목록·코드를 표시하는 글쓰기 형식이에요. `.md` 파일로 저장하고, GitHub와 VS Code가 보기 좋은 문서로 바꿔 보여 줘요. `# 제목`은 큰 제목, `- 항목`은 목록, 백틱 세 개로 감싼 부분은 코드 상자가 돼요.

### README
- 처음 등장: [P1 Day 29](#/day/p1-d29)

프로젝트 폴더 맨 위에 두는 설명서 파일로, 보통 `README.md`라는 이름의 Markdown 파일이에요. 무엇을 만든 프로젝트인지, 어떻게 열고 쓰는지, 폴더 구조가 어떤지 적어요. GitHub는 저장소 첫 화면에 README 내용을 자동으로 보여 줘요.
