이 교재는 프로그래밍을 처음 배우는 사람이 Windows 11 컴퓨터 한 대로 웹사이트를 처음부터 끝까지 만들어 보도록 짠 교재예요. 하루에 1~2시간, Day 하나씩 따라가면 돼요. 여기서는 교재를 쓰는 법, 공부하는 원칙, 전체 지도, 준비물을 알려 드려요. 다 읽는 데 10분쯤 걸려요.

:::tip 바로 시작하고 싶다면
이 페이지는 나중에 다시 봐도 괜찮아요. [P1 Day 1 · 컴퓨터와 웹의 첫걸음](#/day/p1-d01)부터 시작하세요. Day 1에는 미리 설치할 것이 없어요.
:::

## 교재 화면 둘러보기

교재는 `index.html` 파일 하나로 동작해요. 인터넷에 연결되어 있지 않아도 열리고, 바깥으로 아무것도 보내지 않아요.

- **위쪽 줄:** 왼쪽의 **☰ 메뉴**(좁은 화면에서 목차 열기), 가운데 **검색** 칸, 오른쪽의 **🌙 테마**(밝게·어둡게 바꾸기)와 **⚙ 설정**이 있어요.
- **왼쪽 목차:** 프로젝트별 Day 목록이에요. 각 Day 앞의 표시로 진도를 알 수 있어요.
  - 🔒 잠김: 아직 열리지 않은 프로젝트예요.
  - ▶ 다음 할 Day: 오늘 할 차례예요.
  - ✅ 완료: 끝낸 Day예요.
- **홈:** 전체 진도(완료한 Day 수와 %), 프로젝트 지도, **이어서 하기** 버튼이 있어요. 며칠 쉬었다 와도 **이어서 하기**를 누르면 할 차례인 Day로 가요.
- **부록:** 이 페이지(시작하기), [막혔을 때 탈출 가이드](#/page/help), [용어 사전](#/page/glossary), [문제 해결 모음](#/page/troubleshooting)이 목차 아래쪽에 있어요.

Day 본문 안에는 이런 도움이 있어요.

- **코드 상자 오른쪽 위의 복사 버튼:** 누르면 코드가 복사되고 글자가 **복사됨**으로 바뀌어요.
- **밑줄 친 낱말:** 누르면 용어 사전의 그 낱말로 가요.
- **초록색 "이렇게 보이면 성공" 상자:** 단계마다 내 화면과 비교하는 기준이에요.
- **📂 시작 상태 상자:** 그날을 시작할 때 있어야 할 파일 목록이에요. 다르면 상자 안의 링크로 앞 Day의 끝 상태 코드를 가져와 맞춰요.

## 진도와 해금

- 각 Day 맨 아래의 **Day 완료** 버튼을 누르면 그 Day가 ✅ 완료가 돼요. 실수로 눌렀으면 **완료 취소**를 누르면 돼요.
- **Day 완료**는 앞 Day를 완료해야 누를 수 있어요. 순서대로 해야 빠뜨리는 내용이 없기 때문이에요. 버튼이 눌리지 않으면 버튼 옆의 안내 문장을 읽고, 목차에서 ✅가 아닌 앞 Day를 찾아보세요.
- 프로젝트는 차례로 열려요(해금). 잠긴 프로젝트는 본문이 보이지 않아요. 열린 프로젝트의 Day는 완료하지 않았어도 미리 읽어 볼 수 있어요.
- 체크리스트(`📝 오늘의 체크리스트`)의 네모 칸은 눌러서 체크할 수 있고, 체크한 것이 저장돼요.
- 위쪽 **검색** 칸에 낱말이나 오류 메시지를 넣으면 교재 전체에서 찾아 줘요. 잠긴 프로젝트의 결과는 제목만 보여요.

## 정답 보는 법

과제의 정답은 `✅ 정답` 아래에 접혀 있어요. 처음 펼치려고 하면 **잠깐, 먼저 직접 풀어 보세요.** 라는 확인이 나와요.

- 충분히 풀어 봤다면 **그래도 정답 볼래요**를 눌러요.
- 조금 더 해 보고 싶으면 **조금 더 풀어 볼게요**를 눌러요.

정답 맨 끝에는 언제나 **오늘 끝 상태 전체 코드**가 있어요. 그날 따라하기와 과제를 모두 끝낸 모습의 코드예요. 막혀서 더 못 가겠으면 이 코드로 내 파일을 맞추고 다음 Day로 넘어가도 괜찮아요. 방법은 [막혔을 때 탈출 가이드](#/page/help)의 "오늘 끝 상태 코드로 따라잡기"에 있어요.

## 진도 백업과 옮기기

진도(완료한 Day, 체크리스트)는 **지금 쓰는 브라우저 안**에 저장돼요. 그래서 이런 경우에는 진도가 안 보일 수 있어요.

- 브라우저의 방문 기록·사이트 데이터를 지웠을 때
- 다른 브라우저(예: Edge에서 Chrome으로)나 다른 컴퓨터로 열었을 때
- InPrivate·시크릿 창으로 열었을 때(창을 닫으면 사라져요)
- 교재 파일을 다른 곳으로 옮겼을 때(그래서 `C:\dev` 프로젝트 폴더 밖, 예: 문서 폴더에 두고 옮기지 마세요. 프로젝트의 `index.html`과 이름이 같아 섞이기 쉬워요)

그러니 일주일에 한 번쯤, 그리고 프로젝트를 하나 끝낼 때마다 백업 파일을 만들어 두세요.

1. 위쪽 줄 오른쪽의 **⚙ 설정**을 눌러요.
2. **진도 백업** 아래의 **진도 내보내기**를 눌러요.
3. 다운로드 폴더에 `web-zero-to-hundred-progress-날짜.json` 파일이 생겨요. 이 파일을 `C:\dev` 같은 알기 쉬운 곳으로 옮겨 두세요.

다른 브라우저나 컴퓨터에서 이어서 하려면 **⚙ 설정 → 진도 불러오기**를 누르고 그 파일을 골라요. 지금 진도를 덮어쓸지 묻는 창이 뜨면 내용을 읽고 **확인**을 눌러요.

:::warn 진도 모두 지우기는 되돌릴 수 없어요
**⚙ 설정 → 진도 초기화**의 **진도 모두 지우기**는 완료 기록과 체크리스트를 모두 지워요. 누르기 전에 꼭 **진도 내보내기**로 백업해 두세요.
:::

:::info 저장소를 쓸 수 없다는 안내가 나오면
브라우저 설정 때문에 진도를 저장할 수 없으면 화면 위쪽에 안내가 떠요. 이때 교재는 이 창이 열려 있는 동안만 진도를 기억해요. 창을 닫기 전에 **진도 내보내기**를 해 두세요.
:::

## 공부하는 원칙 다섯 가지

### 1. 직접 타이핑해요

처음에는 코드를 직접 쳐 보세요. 손으로 치면서 괄호·따옴표·세미콜론이 어디에 붙는지 몸이 기억해요. 오타가 나서 고치는 과정도 공부예요. 다만 시간이 모자라거나 긴 코드(그림 파일, 데이터 파일)는 복사 버튼을 써도 괜찮아요. 교재의 모든 코드 상자는 그대로 붙여 넣으면 동작하게 만들었어요.

### 2. 성공 상자를 확인하고 넘어가요

단계마다 초록색 성공 상자와 내 화면을 비교해요. 다르면 다음 단계로 가지 말고, 그 Day의 `🧯 자주 막히는 곳`을 먼저 보세요. 작은 차이를 그냥 넘기면 몇 단계 뒤에 원인을 찾기 훨씬 어려워져요.

### 3. 30분 규칙

한 문제로 **30분** 넘게 막히면 혼자 버티지 말고 [막혔을 때 탈출 가이드](#/page/help)를 열어요. 오류 메시지 읽는 법, 내 파일과 정답 비교하는 법, 질문하는 법이 있어요. 그래도 안 되면 그날의 끝 상태 코드로 맞추고 다음 날 다시 봐요. 막힌 곳은 잠을 자고 나서 보면 의외로 쉽게 보이기도 해요.

### 4. 하루에 Day 하나

Day 하나는 1~2시간 분량이에요. 하루에 여러 Day를 몰아서 하기보다 매일 조금씩 하는 편이 오래 기억에 남아요. 며칠 빠졌다면 앞 Day의 체크리스트를 한 번 훑어보고 시작하세요.

### 5. 매일 저장하고 기록해요

P1 Day 7부터는 Git으로 그날 한 일을 커밋하고 GitHub에 올려요. 그러면 컴퓨터에 문제가 생겨도 내 코드가 인터넷에 남고, 잘못 고쳤을 때 되돌릴 수 있어요.

:::tip 다 이해하지 못해도 괜찮아요
처음 보는 개념이 한 번에 이해되지 않는 것은 정상이에요. 중요한 개념은 뒤 Day에서 여러 번 다시 나와요. 성공 상자가 보이고 체크리스트를 채울 수 있다면 다음 Day로 가도 돼요.
:::

## 전체 지도

프로젝트는 모두 네 개, Day는 모두 155개예요. 하루 한 Day씩이면 5~6개월쯤 걸려요.

```text
P1 크리에이터 홈페이지 (30일)
        │
        ▼
P2 스트리머 허브 (40일)
        │
   ┌────┴─────┐
   ▼          ▼
P3 게임     SP 이미지
(45일)      도네이션(40일)
   │
   ▼
졸업 로드맵
```

- **P1 나의 크리에이터 홈페이지(30 Day):** HTML·CSS·JavaScript로 내 방송 홈페이지와 OBS 카운트다운 오버레이를 만들고, Git·GitHub로 관리하며 GitHub Pages로 인터넷에 공개해요. 작업 폴더 `C:\dev\my-creator-site`
- **P2 스트리머 허브(40 Day):** P1을 끝내면 열려요. TypeScript와 C#으로 화면과 서버를 함께 만들고, 데이터베이스와 로그인을 다뤄요. 작업 폴더 `C:\dev\streamer-hub`
- **P3 시청자 참여 실시간 게임(45 Day):** P2를 끝내면 열려요. Rust로 서버와 게임 로직을 만들고, 시청자가 휴대폰으로 참여하는 게임을 OBS에 띄워요. 작업 폴더 `C:\dev\viewer-arena`
- **SP 특별 프로젝트: 이미지 도네이션(40 Day):** P2를 끝내면 언제든 열려요(P3 전에 해도, 뒤에 해도 돼요). 시청자가 보낸 이미지를 검수해 방송에 띄우는 서비스를 만들어요. 결제는 다루지 않아요. 작업 폴더 `C:\dev\image-donation`
- **졸업 로드맵:** P3를 끝내면 열려요. 다음에 배울 길과 다음 프로젝트 후보를 정리해요.

모든 실습 폴더는 `C:\dev` 안에 만들어요. 바탕 화면·문서·OneDrive 폴더나 한글·빈칸이 들어간 폴더는 쓰지 않아요. 이유는 [P1 Day 1](#/day/p1-d01)에서 설명해요.

## 준비물

- **Windows 11 컴퓨터 한 대.** Home·Pro 모두 괜찮아요. 교재의 화면 설명과 명령은 Windows 11과 PowerShell 기준이에요(작성 기준일 2026-11). 메뉴 이름은 버전에 따라 조금 다를 수 있어요.
- **설치 권한.** 프로그램을 설치할 때 "이 앱이 디바이스를 변경하도록 허용하시겠어요?" 같은 확인 창(사용자 계정 컨트롤)이 뜰 수 있어요. 회사·학교 컴퓨터는 설치가 막혀 있을 수 있으니 개인 컴퓨터를 권해요.
- **인터넷.** 프로그램 설치, GitHub 가입, 배포를 하는 Day에는 인터넷이 필요해요(P1에서는 Day 2, 7, 14, 27 등). 그 Day 본문에 따로 적어 두었어요. 교재를 읽는 것은 인터넷 없이도 돼요.
- **이메일 주소 하나.** P1 Day 7에서 GitHub에 가입할 때 써요. 인증 메일을 받을 수 있어야 해요.
- **하루 1~2시간.** 조용히 집중할 수 있는 시간이면 좋아요.
- **(선택) 휴대폰.** P1 Day 14에 사이트를 공개한 뒤, 휴대폰으로 내 사이트가 잘 보이는지 확인할 때 써요.
- **(선택) OBS Studio.** P1 Day 27에서 방송 화면에 카운트다운을 띄울 때 설치해요. 설치하지 않아도 브라우저로 끝까지 따라갈 수 있어요.

미리 설치할 것은 없어요. 필요한 도구는 처음 쓰는 Day에 설치 방법과 확인 방법을 함께 알려 드려요.
