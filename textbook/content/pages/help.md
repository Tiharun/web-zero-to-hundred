막히는 건 실력이 없어서가 아니에요. 개발자는 매일 막히고, 막혔을 때 빠져나오는 순서를 알고 있을 뿐이에요. 이 페이지는 그 순서를 알려 드려요. 위에서부터 차례로 해 보세요.

```text
① 숨 고르기 (30분 규칙)
   ▼
② 오류 메시지 읽기
   ▼
③ 정답과 내 파일 비교하기
   ▼
④ 끝 상태 코드로 따라잡기
   ▼
⑤ AI·커뮤니티에 질문하기
```

:::tip 먼저 찾아볼 곳
그날 Day의 `🧯 자주 막히는 곳`과 [문제 해결 모음](#/page/troubleshooting)에 흔한 문제가 증상별로 모여 있어요. 화면 위쪽 **검색** 칸에 오류 메시지 앞부분(예: `Cannot read properties of null`)을 넣어 찾아봐도 돼요.
:::

## 1. 숨 고르기: 30분 규칙

- 같은 문제로 **30분**이 지나면 손을 멈추고 이 페이지의 다음 순서로 넘어가요. 같은 곳을 계속 고치면 실수가 늘어나요.
- 의자에서 일어나 5분만 쉬어요. 물을 마시고 돌아와서 성공 상자를 처음부터 다시 읽어 보세요. 생각보다 자주, 쉬고 나면 오타가 보여요.
- 그날 공부 시간이 끝났다면 그날은 아래 4번 "오늘 끝 상태 코드로 따라잡기"로 맞추고 쉬어요. 다음 날 맑은 머리로 다시 보면 돼요.

## 2. 오류 메시지 읽는 법

오류 메시지는 컴퓨터가 "여기가 이상해요"라고 알려 주는 단서예요. 영어라서 겁나 보이지만, 읽는 순서는 늘 같아요.

### 오류는 어디에 나오나요?

- **브라우저 콘솔:** `F12`(노트북은 `Fn + F12`)로 개발자 도구를 열고 **Console**(콘솔) 탭을 눌러요. 빨간 글자가 JavaScript 오류예요.
- **VS Code 편집기:** 코드 아래 빨간 물결 밑줄이 문법 오류예요. 밑줄에 마우스를 올리면 설명이 나와요.
- **터미널:** Git 명령의 결과에 `fatal:`이나 `error:`로 시작하는 줄이 나오면 오류예요.
- **화면:** 그림 대신 깨진 그림 표시, "찾을 수 없음" 페이지, 아무 변화 없음도 단서예요. 이때는 콘솔과 **Network**(네트워크) 탭을 같이 봐요.

### 네 부분으로 나눠 읽어요

브라우저 콘솔의 오류 한 줄을 예로 들어 볼게요.

```text
Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')
```

1. **종류:** `TypeError` — 값의 종류가 맞지 않다는 뜻이에요. 자주 보는 종류는 `ReferenceError`(없는 이름을 씀), `SyntaxError`(문법이 틀림), `TypeError`(값이 생각과 다름)예요.
2. **문장:** `Cannot read properties of null` — "`null`(아무것도 없음)에서 속성을 읽을 수 없어요." 즉 찾으려던 요소가 없었다는 뜻이에요. 문장이 어려우면 번역기에 통째로 넣어도 괜찮아요.
3. **괄호 속 힌트:** `(reading 'addEventListener')` — `addEventListener`를 쓰려다 멈췄다는 뜻이에요.
4. **위치:** 오류 줄 오른쪽(또는 아래)에 `main.js:9`처럼 파일 이름과 줄 번호가 보여요. 누르면 그 줄로 가요. 숫자는 사람마다 달라요.

그다음에는 이렇게 해요.

1. 알려 준 줄과 **바로 위 몇 줄**을 봐요. 원인은 그 줄보다 위에 있는 경우가 많아요(예: 위 줄에서 `querySelector`의 이름을 틀림).
2. 이름의 철자와 대소문자를 HTML과 하나하나 맞춰 봐요(`#site-nav`와 `id="site-nav"`).
3. 오류가 여러 개면 **맨 위의 첫 번째 오류**부터 고쳐요. 뒤의 오류는 첫 오류 때문에 생긴 경우가 많아요.
4. 고쳤으면 저장(`Ctrl + S`)하고 브라우저 탭을 클릭해서 새로 고쳐(`F5`) 오류가 사라졌는지 봐요. 그대로면 `Ctrl + F5`로 강력 새로 고침해요. VS Code 안의 미리 보기 창은 저장하면 저절로 바뀌니 거기서는 `F5`를 누르지 마세요(VS Code에서는 프로그램 실행 키예요).

터미널 오류도 같은 방법으로 읽어요. 예를 들어 Git이 관리하지 않는 폴더에서 Git 명령을 치면 이렇게 나와요.

```text
fatal: not a git repository (or any of the parent directories): .git
```

"여기(와 그 위 폴더들)는 Git 저장소가 아니에요"라는 뜻이에요. 터미널의 `PS C:\…>` 부분에서 지금 위치를 확인하고, 프로젝트 폴더로 옮겨 가면 해결돼요.

### 자주 보는 낱말

| 오류 속 낱말 | 뜻 | 먼저 볼 곳 |
|---|---|---|
| `is not defined` | 그런 이름이 없어요 | 이름 철자 |
| `null` | 찾은 요소가 없어요 | 선택자와 HTML의 id |
| `Unexpected token` | 문법 기호가 이상해요 | 괄호·따옴표·쉼표 |
| `404` | 파일이 없어요 | 경로·파일 이름 |
| `not recognized` | 그런 명령이 없어요 | 설치 후 창 다시 열기 |

## 3. 정답과 내 파일 비교하기

정답 코드와 내 코드를 눈으로 한 줄씩 비교하면 놓치기 쉬워요. VS Code는 두 파일을 나란히 놓고 **다른 곳만 색으로 표시**해 줘요.

### 3-1. 정답 코드를 새 탭에 붙여 넣기

1. 교재의 `✅ 정답`에서 비교할 코드 상자의 **복사** 버튼을 눌러요.
2. VS Code에서 `Ctrl + N`을 눌러 이름 없는 새 탭을 열어요. 영어 화면에서는 탭 이름이 `Untitled-1`이고, 한국어 화면에서는 다른 이름으로 보일 수 있어요. 저장하지 않아도 돼요.
3. 새 탭을 클릭하고 `Ctrl + V`로 붙여 넣어요.

### 3-2. 명령 팔레트로 비교하기

1. VS Code에서 **내 파일**(예: `C:\dev\my-creator-site\css\style.css`)의 탭을 클릭해 앞에 둬요.
2. `Ctrl + Shift + P`로 명령 팔레트를 열어요.
3. `File: Compare Active File With...`를 입력하고 `Enter`를 눌러요. 한국어 VS Code에서는 이 명령이 한국어 이름으로 보일 수 있지만, 영어로 입력해도 찾아져요(문구는 버전에 따라 조금 다를 수 있어요).
4. 나오는 목록에서 방금 붙여 넣은 이름 없는 탭(`Untitled-1`)을 골라요.

:::success
편집기가 둘로 나뉘어 왼쪽에 내 파일, 오른쪽에 정답이 보여요. 서로 다른 줄은 빨간색·초록색 배경으로 표시돼요.
:::

목록에 이름 없는 탭이 보이지 않으면 다른 방법을 써요. VS Code 왼쪽 **탐색기** 맨 위의 **열려 있는 편집기** 목록에서 내 파일을 오른쪽 클릭해 **비교를 위해 선택**을 누르고, 이름 없는 탭을 오른쪽 클릭해 **선택한 항목과 비교**를 눌러요(메뉴 이름은 버전에 따라 조금 다를 수 있어요. **열려 있는 편집기** 목록이 안 보이면 탐색기 오른쪽 위 **⋯** 메뉴에서 켤 수 있어요).

### 3-3. 차이를 읽는 요령

- 빨간색은 한쪽에만 있거나 다른 줄, 초록색은 다른 쪽에만 있거나 다른 줄이에요. 줄 안에서 진하게 칠해진 글자가 정확히 다른 부분이에요.
- 들여쓰기·빈 줄 차이는 동작에 영향이 거의 없어요. 괄호·따옴표·세미콜론·쉼표·철자·대소문자 차이를 먼저 봐요.
- 글 내용(닉네임, 소개 문장, 영상 제목)은 달라도 괜찮아요. class·id·파일 이름은 정답과 똑같아야 해요.
- 다 봤으면 비교 탭과 이름 없는 탭을 닫아요. 저장할지 물으면 **저장 안 함**을 눌러요.

## 4. 오늘 끝 상태 코드로 따라잡기

모든 Day의 `✅ 정답` 맨 끝에는 **오늘 끝 상태 전체 코드**가 있어요. 그날 따라하기와 과제를 모두 끝냈을 때의 폴더 모양과, 그날 바뀐 파일의 코드예요. 오래 막혔다면 이 코드로 내 파일을 맞추고 다음 Day를 시작해도 괜찮아요. 막힌 부분은 메모해 두었다가 나중에 다시 보면 돼요.

### 4-1. 지금 내 작업을 먼저 보관해요

내가 쓴 코드를 덮어쓰기 전에 보관해 두면, 나중에 무엇이 달랐는지 비교해 볼 수 있어요.

- **Git을 배운 뒤(P1 Day 7부터):** VS Code **소스 제어** 패널(`Ctrl + Shift + G`)에서 메시지에 `Day 12: 막힌 상태 보관`처럼 적고 커밋해요. 나중에 GitHub에서 이 커밋을 보면 내 코드가 남아 있어요.
- **Git을 배우기 전:** 파일 탐색기에서 프로젝트 폴더(예: `C:\dev\my-creator-site`)를 오른쪽 클릭해 복사하고, `C:\dev`에 붙여 넣은 뒤 이름을 `my-creator-site-day05-backup`처럼 바꿔요. 이 백업 폴더는 VS Code로 열지 않아요.

### 4-2. 끝 상태 코드로 덮어써요

1. 오늘 Day의 `✅ 정답` → **오늘 끝 상태 전체 코드**를 펼쳐요.
2. 맨 위의 폴더 트리와 내 폴더를 비교해요. 없는 폴더·파일은 VS Code 탐색기에서 같은 이름으로 만들어요.
3. 코드 상자 위의 `📄 C:\dev\…` 경로를 보고, VS Code에서 그 파일을 열어요.
4. 교재 코드 상자의 **복사** 버튼을 누르고, VS Code에서 `Ctrl + A`(전체 선택) → `Ctrl + V`(붙여 넣기) → `Ctrl + S`(저장)를 해요.
5. 코드 상자 위 경로 끝에 `(일부)`가 붙어 있으면 파일 전체가 아니라 일부예요. 상자 바로 위 문장이 알려 주는 위치(예: "`</main>` 줄 바로 앞")에 붙여 넣어요.
6. 바뀐 파일마다 3~5를 되풀이해요.
7. 브라우저에서 `F5`로 새로 고치고, 그날의 체크리스트 항목이 화면에 보이는지 확인해요.

:::warn 바로 앞 Day의 끝 상태를 써요
내일 Day를 시작하려면 **오늘** Day의 끝 상태가 필요해요. 며칠을 건너뛰어 더 뒤의 Day 코드를 가져오면 아직 배우지 않은 코드가 섞여요. 며칠 밀렸다면 마지막으로 끝낸 Day의 **다음 Day부터 차례로** 그날 바뀐 파일의 코드를 적용해요. 각 Day의 `📂 시작 상태` 상자에 있는 링크가 알맞은 끝 상태로 안내해요.
:::

## 5. AI나 커뮤니티에 질문하기

교재와 이 페이지로도 해결이 안 되면 AI 도우미나 개발자 커뮤니티에 물어봐도 좋아요. 좋은 질문에는 **어디서, 무엇을 했고, 무엇을 기대했는데, 실제로는 어땠는지**가 들어 있어요. 아래 틀을 복사해서 채워 보세요.

```text
[교재] 웹 제로 투 헌드레드 P1 Day 12 · Grid
[환경] Windows 11, Chrome, VS Code
[하려던 것] 따라하기 3단계: 홈 카드 3장을 한 줄로 놓기
[한 일] css\style.css에 .card-grid 규칙을 넣고 저장한 뒤 새로 고침
[기대한 결과] 넓은 화면에서 카드 3장이 한 줄로 보임
[실제 결과] 카드가 세로로만 쌓임
[오류 원문] (콘솔이나 터미널의 빨간 글자를 그대로 복사해 붙여요)
[관련 코드] (문제가 있는 파일에서 관련된 부분만 붙여요)
[이미 해 본 것] Ctrl + F5로 새로 고침, class 이름 철자 확인
```

- **Day 번호와 단계**를 꼭 적어요. 어디까지 배웠는지 알아야 알맞은 답을 줄 수 있어요.
- **오류 원문**은 사진이 아니라 글자로 복사해 붙여요. 콘솔 오류는 마우스로 끌어 선택한 뒤 `Ctrl + C`로 복사할 수 있어요.
- **스크린샷**이 필요하면 `Win + Shift + S`를 누르고 화면 일부를 끌어 선택해요. 캡처한 그림은 붙여 넣기(`Ctrl + V`)로 질문에 넣을 수 있어요.
- **비밀은 지워요.** 비밀번호, 인증 코드, 토큰, 주민 번호·전화번호·주소 같은 개인 정보는 질문에 넣지 않아요. 스크린샷에 보이면 가리고 올려요.

:::warn AI의 답은 확인하고 써요
AI는 그럴듯하지만 틀린 답을 줄 때가 있어요. 그리고 교재에서 아직 배우지 않은 방법이나 다른 파일 이름을 쓰라고 할 수도 있어요. 답을 통째로 붙여 넣지 말고, 한 줄씩 이해한 뒤 내 코드에 고쳐 넣어요. 파일·class·id 이름은 교재와 똑같이 유지해야 다음 Day가 맞아요. 고친 뒤에는 교재의 성공 상자로 결과를 확인해요.
:::

## 6. 쉬어 가기 규칙

- **하루 2시간을 넘기지 않아요.** 지친 상태에서는 실수가 늘고 배운 것도 덜 남아요.
- **막힌 채로 끝나도 괜찮아요.** 끝 상태 코드로 맞추고, 막힌 곳을 한 줄 메모해 두세요. 다음 날 그 메모부터 다시 보면 돼요.
- **며칠 쉬어도 괜찮아요.** 홈의 **이어서 하기**를 누르면 할 차례인 Day로 가요. 오래 쉬었다면 앞 Day의 체크리스트를 먼저 훑어보세요.
- **같은 Day를 두 번 해도 돼요.** 어려웠던 Day는 다음 날 처음부터 다시 따라 해 보면 훨씬 빨리 끝나요. 그만큼 실력이 늘었다는 뜻이에요.
- **잘한 것을 세어 봐요.** 오늘 성공 상자를 몇 개 봤는지, 어떤 오류를 혼자 고쳤는지 적어 두면 다음 막힘을 이길 힘이 돼요.
