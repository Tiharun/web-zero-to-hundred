# P2 문제 해결 (Day 11~20)

### `warning CS8602: Dereference of a possibly null reference.`
- 관련: [P2 Day 11](#/day/p2-d11)

```text
C:\dev\cs-practice\Program.cs(61,19): warning CS8602: Dereference of a possibly null reference. [C:\dev\cs-practice\HubConsole.csproj]
```

**원인:** `string?`처럼 null일 수 있는 값에 null 확인 없이 `.`을 붙였어요. 경고라서 실행은 되지만 값이 null이면 `NullReferenceException`으로 멈춰요.

**해결:** 그 줄 앞에서 `if (값 is null)`로 확인하거나, `값?.Length`, `값 ?? "기본"`을 써요. Day 11의 5단계 끝을 다시 보세요.

### `Unhandled exception. System.Collections.Generic.KeyNotFoundException`
- 관련: [P2 Day 11](#/day/p2-d11)

```text
Unhandled exception. System.Collections.Generic.KeyNotFoundException: The given key '없는키' was not present in the dictionary.
```

**원인:** Dictionary에 없는 키를 `counts["없는키"]`로 꺼냈어요.

**해결:** 먼저 `ContainsKey("없는키")`로 확인하거나 `TryGetValue`, `GetValueOrDefault`를 써요. 예외를 다루는 법은 Day 15에서 배워요.

### `ArgumentOutOfRangeException: Index was out of range.`
- 관련: [P2 Day 11](#/day/p2-d11)

```text
Unhandled exception. System.ArgumentOutOfRangeException: Index was out of range. Must be non-negative and less than the size of the collection. (Parameter 'index')
```

**원인:** `names[5]`처럼 List 크기보다 큰 번호로 꺼냈어요. 번호는 0부터 `Count - 1`까지예요.

**해결:** `names.Count`를 확인하고 번호를 고쳐요.

### `InvalidOperationException: Collection was modified; enumeration operation may not execute.`
- 관련: [P2 Day 11](#/day/p2-d11)


**원인:** `foreach`로 돌아보는 중에 같은 목록에 `Remove`나 `Add`를 했어요.

### `error CS0136: A local or parameter named '…' cannot be declared in this scope`
- 관련: [P2 Day 14](#/day/p2-d14)


**원인:** 같은 이름(`item`)을 바깥(파일 맨 위 수준)에서 변수로 이미 만들었는데 안쪽 `foreach`에서 또 만들었어요. 줄 번호는 사람마다 달라요. 같은 칸에 같은 이름을 두 번 만들면 `CS0128`(`already defined in this scope`)이 나와요.

### `OrderBy`를 두 번 썼더니 앞 정렬이 사라졌어요
- 관련: [P2 Day 14](#/day/p2-d14)

**원인:** `.OrderBy(a).OrderBy(b)`는 두 번째가 전체를 새로 정렬해서 첫 번째 기준이 의미가 없어져요.

**해결:** 첫 기준이 같을 때 두 번째 기준으로 정하려면 `.OrderBy(a).ThenBy(b)`를 써요.

- 관련: [P2 Day 14](#/day/p2-d14)

**원인:** `Skip`이 전체 개수보다 크면 건너뛰고 남는 것이 없어요. `page`를 0부터 센 경우도 있어요.

**해결:** `page`는 1부터 세요. `(page - 1) * pageSize`로 계산해요.

### `error CS4033: The 'await' operator can only be used within an async method.`
- 관련: [P2 Day 15](#/day/p2-d15)

```text
C:\dev\cs-practice\Program.cs(8,16): error CS4033: The 'await' operator can only be used within an async method. Consider marking this method with the 'async' modifier and changing its return type to 'Task'.
```

**원인:** `await`를 `async`가 없는 메서드 안에서 썼어요. 파일 맨 위 문장에서는 괜찮지만, `void PrintAll()` 같은 메서드 안에서는 안 돼요.

### `warning CS4014: Because this call is not awaited, …`

### 응답이 `Error: getaddrinfo ENOTFOUND …`이거나 아무것도 안 와요

**원인:** `@host`의 아이디나 저장소 이름이 틀렸거나(대소문자 포함), 인터넷이 끊겼어요. 주소 중간의 `my-creator-site`는 P1에서 만든 GitHub 저장소 이름이에요.

### `Failed to bind to address http://127.0.0.1:5250: address already in use.`
- 관련: [P2 Day 17](#/day/p2-d17)

```text
fail: Microsoft.Extensions.Hosting.Internal.Host[11]
      Hosting failed to start
      System.IO.IOException: Failed to bind to address http://127.0.0.1:5250: address already in use.
```

**원인:** 5250번 포트를 다른 프로그램이 이미 쓰고 있어요. 대부분 내가 앞서 켜 둔 서버(`dotnet watch`)가 다른 터미널에 남아 있거나, 창만 닫고 서버를 끄지 않은 경우예요. 아래쪽에 이어지는 줄은 컴퓨터마다 달라요(Windows에서는 다른 문장이 나와요).

**해결:**

1. 서버를 켜 둔 다른 터미널이 있으면 그 터미널을 클릭하고 `Ctrl + C`로 꺼요.
2. 터미널을 찾을 수 없으면 PowerShell에서 5250번을 쓰는 프로그램을 찾아요.

```powershell
Get-NetTCPConnection -LocalPort 5250
```

예상 출력(열 이름과 숫자는 달라도 돼요. `OwningProcess` 열의 번호를 기억해요):

```text
LocalAddress LocalPort RemoteAddress RemotePort State  AppliedSetting OwningProcess
------------ --------- ------------- ---------- -----  -------------- -------------
127.0.0.1    5250      0.0.0.0       0          Listen                12345
```

3. 그 번호가 내 서버인지 확인해요. `12345`를 내 번호로 바꿔요.

```powershell
Get-Process -Id 12345
```

`ProcessName` 열이 `StreamerHub.Api` 또는 `dotnet`이면 내가 켠 서버예요.

4. 내 서버가 맞을 때만 꺼요. 모르는 프로그램이면 건드리지 않고 Day 17 과제 1처럼 포트를 바꿔요.

```powershell
Stop-Process -Id 12345
```

5. `dotnet watch`를 다시 실행하면 `Now listening on: http://localhost:5250`이 나와요.

### POST를 보냈더니 `415 Unsupported Media Type`이 와요

### `error CS0029: Cannot implicitly convert type '…NotFound' to '…Ok<…>'`
- 관련: [P2 Day 18](#/day/p2-d18)

```text
C:\dev\streamer-hub\server\StreamerHub.Api\Program.cs(67,16): error CS0029: Cannot implicitly convert type 'Microsoft.AspNetCore.Http.HttpResults.NotFound' to 'Microsoft.AspNetCore.Http.HttpResults.Ok<StreamerHub.Api.Entities.Streamer>'
```

### `sqlite3`가 인식되지 않아요
- 관련: [P2 Day 19](#/day/p2-d19)

```text

```

한국어 Windows에서는 `'sqlite3' 용어가 cmdlet, 함수, 스크립트 파일 또는 실행할 수 있는 프로그램 이름으로 인식되지 않습니다.`로 보여요(문구는 버전에 따라 달라요).


이 방법이면 PATH 설정이 필요 없어요. `sqlite3`만 쳐서 쓰고 싶으면 시작 메뉴에서 "환경 변수"를 검색해 **계정에 대한 환경 변수 편집** → 사용자 변수의 `Path` 선택 → **편집** → **새로 만들기**에 `C:\dev\tools\sqlite` 입력 → 모두 **확인**을 누르고 새 터미널을 열어요(이 메뉴의 정확한 문구는 실기 확인 전이라 달라질 수 있어요).

**원인:** `Sqlite`와 `Design` 패키지의 버전이 서로 달라요(예: 하나는 10.0.14, 하나는 다른 값).

**해결:** `StreamerHub.Api.csproj`를 열어 두 `PackageReference`의 `Version`을 모두 `10.0.14`로 맞추고 `dotnet build`를 다시 실행해요.

### 오류 문장이 한국어로 나와요 (컴파일러 `error`·`warning`)
- 관련: [P2 Day 11](#/day/p2-d11)

**원인:** 한국어 Windows에서는 `dotnet build`·`dotnet run`이 보여 주는 컴파일러 문장이 한국어로 나와요. 예: `error CS0029: 암시적으로 'string' 형식을 'int' 형식으로 변환할 수 없습니다.` 이 책의 영어 문장은 같은 오류의 영어 원문이에요. 프로그램이 실행 중에 던지는 `Unhandled exception.`은 영어로 나와요.

**해결:**

1. 문장 대신 `CS`로 시작하는 번호(예: `CS0029`)와 `Program.cs(3,19)`처럼 줄·칸 번호를 읽어요. 번호는 언어와 관계없이 같아요.
2. 이 문제 해결 모음이나 해당 Day의 🧯에서 같은 번호의 항목을 찾아요.
3. 번호가 같은 항목을 찾았고 그 줄을 고친 뒤 `dotnet build`의 오류가 사라지면 해결이에요.

### `StreamerHub.slnx`가 아니라 다른 솔루션 파일이 생겼어요
- 관련: [P2 Day 17](#/day/p2-d17)

**원인:** `dotnet new sln`이 만드는 파일 모양은 .NET SDK 버전에 따라 달라요. 이 책은 .NET 10 SDK에서 확인했고, 거기서는 `.slnx`가 만들어져요. 다른 SDK 버전이면 `.sln`이 만들어질 수 있어요.

**해결:**

1. `dotnet --version`을 입력해 `10.0.`으로 시작하는지 확인해요. 아니면 [Day 3](#/day/p2-d03)·[Day 9](#/day/p2-d09)의 설치 안내대로 .NET 10 SDK를 설치하고 새 터미널을 열어요.
2. `server` 폴더의 솔루션 파일을 지우고 `dotnet new sln -n StreamerHub`와 `dotnet sln add StreamerHub.Api`를 다시 실행해요.
3. `dir`에 `StreamerHub.slnx`가 보이면 해결이에요.
