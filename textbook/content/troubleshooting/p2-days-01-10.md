# P2 문제 해결 (Day 1~10)

### Network 탭이 비어 있어요 (개발자 도구)
- 관련: [P2 Day 1](#/day/p2-d01)

**원인:** Network 탭은 탭을 연 뒤에 일어난 요청만 기록해요. 페이지를 먼저 열고 개발자 도구를 나중에 열면 그 전의 요청은 목록에 없어요.

**해결:**

1. 개발자 도구(`F12`)에서 **Network** 탭을 클릭해요. 한국어 화면에서는 **네트워크**예요.
2. 페이지로 마우스를 옮기고 `F5`를 눌러 새로 고침해요.
3. 목록에 줄이 나타나면 해결이에요.

### `Fetch API cannot load file:///…` (P1 사이트를 더블클릭으로 열었어요)
- 관련: [P2 Day 1](#/day/p2-d01)

**원인:** 파일을 더블클릭해서(`file:///C:/…` 주소로) 열면 브라우저 보안 규칙 때문에 `fetch`로 다른 파일을 읽을 수 없어요. 문구는 브라우저와 버전에 따라 조금 달라요. 예: `Fetch API cannot load file:///.../data/videos.json. URL scheme "file" is not supported.`

**해결:**

1. VS Code에서 `contents.html`을 Live Preview로 열고 주소(`http://127.0.0.1:…/contents.html`)를 복사해요.
2. Chrome 또는 Edge 주소 표시줄에 붙여 넣고 `Enter`를 눌러요.
3. Network 탭에 `videos.json`이 `200`으로 보이면 해결이에요.

### `The token '&&' is not a valid statement separator in this version.`
- 관련: [P2 Day 2](#/day/p2-d02)

**원인:** Windows PowerShell 5.1은 `&&`로 명령을 잇는 문법을 지원하지 않아요(PowerShell 7부터 지원). 문구는 버전에 따라 조금 달라요.

**해결:**

1. `&&` 앞뒤의 명령을 한 줄에 하나씩 따로 입력해요.
2. 예: `cd C:\dev && dir`은 `cd C:\dev`를 입력하고 `Enter`, 이어서 `dir`을 입력하고 `Enter`를 눌러요.
3. 오류 없이 각 명령이 실행되면 해결이에요.

### `cd : A positional parameter cannot be found that accepts argument 'folder'.`
- 관련: [P2 Day 2](#/day/p2-d02)

**원인:** 경로에 공백이 있는데 따옴표를 쓰지 않아서 `cd`가 단어를 둘로 나눠 읽었어요. 한국어 Windows에서는 첫 줄이 "위치 매개 변수를 찾을 수 없습니다" 같은 문장으로 번역되어 보일 수 있어요.

**해결:**

1. 경로 전체를 큰따옴표(`"`)로 감싸요. 예: `cd "C:\dev\terminal-practice\my folder"`
2. 프롬프트가 해당 폴더로 바뀌면 해결이에요.

### VS Code 터미널 프롬프트에 `PS`가 없어요 (cmd나 Git Bash로 열렸어요)
- 관련: [P2 Day 2](#/day/p2-d02)

**원인:** VS Code 통합 터미널의 기본 셸이 PowerShell이 아니에요.

**해결:**

1. 터미널 패널 오른쪽 위 `∨`(아래 화살표)를 클릭해 **PowerShell**을 골라요.
2. 계속 같은 셸이 열리면 같은 메뉴의 **기본 프로필 선택**에서 **PowerShell**을 골라요.
3. 프롬프트가 `PS C:\…>`로 시작하면 해결이에요.

### `fatal: not a git repository (or any of the parent directories): .git`
- 관련: [P2 Day 2](#/day/p2-d02)

**원인:** 터미널의 현재 위치가 Git 저장소 안이 아니거나 `git init`을 아직 안 했어요. 터미널을 닫았다 열면 위치가 처음으로 돌아가요.

**해결:**

1. 프롬프트의 경로를 읽어요.
2. `cd C:\dev\streamer-hub`를 입력해요.
3. 그래도 같은 오류면 `dir -Force`로 `.git` 폴더가 있는지 보고, 없으면 `git init`을 실행해요.
4. `git status`에 `On branch main`이 나오면 해결이에요.

### `error: remote origin already exists.`
- 관련: [P2 Day 2](#/day/p2-d02)

**원인:** `git remote add origin …`을 두 번 실행했어요.

**해결:**

1. `git remote -v`로 연결된 주소를 확인해요.
2. 틀렸다면 `git remote set-url origin https://github.com/<내 아이디>/streamer-hub.git`로 고쳐요. `<내 아이디>`는 내 GitHub 아이디로 바꿔요.
3. `git remote -v`가 맞는 주소를 보여 주면 해결이에요.

### `npm : File C:\Program Files\nodejs\npm.ps1 cannot be loaded because running scripts is disabled on this system.`
- 관련: [P2 Day 3](#/day/p2-d03), [P2 Day 7](#/day/p2-d07)

**원인:** Windows PowerShell 5.1의 기본 실행 정책이 `npm.ps1` 스크립트 실행을 막아요(`UnauthorizedAccess`). 한국어 Windows에서는 "이 시스템에서 스크립트를 실행할 수 없으므로 … 파일을 로드할 수 없습니다"로 보여요.

**해결:**

1. 터미널에서 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`를 입력하고 `Enter`를 눌러요. 관리자 권한은 필요 없어요.
2. 질문에 `Y`를 입력하고 `Enter`를 눌러요.
3. `Get-ExecutionPolicy -Scope CurrentUser`가 `RemoteSigned`를 보여 주고 `npm --version`이 숫자를 보여 주면 해결이에요. `Unrestricted`나 `Bypass`로 바꾸지 않아요.

### `node : The term 'node' is not recognized as the name of a cmdlet, function, script file, or operable program.` (`dotnet`도 같아요)
- 관련: [P2 Day 3](#/day/p2-d03), [P2 Day 9](#/day/p2-d09)

**원인:** 설치 전에 열려 있던 터미널이 옛 PATH를 들고 있어요. 한국어 Windows에서는 "'node' 용어가 cmdlet, 함수, 스크립트 파일 또는 실행할 수 있는 프로그램 이름으로 인식되지 않습니다."로 보여요.

**해결:**

1. 열려 있는 터미널과 VS Code를 모두 닫아요.
2. 터미널을 새로 열고 `node --version`(또는 `dotnet --version`)을 입력해요.
3. 그래도 안 되면 설치를 처음부터 다시 해요(`C:\Program Files\nodejs` 또는 `C:\Program Files\dotnet` 폴더가 있는지 확인해요).
4. 버전이 나오면 해결이에요.

### `error TS5112: tsconfig.json is present but will not be loaded if files are specified on commandline.`
- 관련: [P2 Day 4](#/day/p2-d04)

**원인:** `tsconfig.json`이 있는 폴더에서 `npx tsc 파일이름`처럼 파일 이름을 적었어요.

**해결:**

1. 설정대로 변환하려면 파일 이름 없이 `npx tsc`만 입력해요.
2. 설정 없이 파일 하나만 변환하려면 `npx tsc --ignoreConfig src\hello.ts --outDir out`처럼 `--ignoreConfig`를 붙여요.
3. 오류가 사라지면 해결이에요.

### `error TS2591: Cannot find name 'process'.` (또는 `console`)
- 관련: [P2 Day 4](#/day/p2-d04)

**원인:** `@types/node`가 설치되지 않았거나 `tsconfig.json`에 `"types": ["node"]`가 없어요.

**해결:**

1. `npm i -D @types/node`를 실행해요.
2. `tsconfig.json`에 `"types": ["node"]`가 있는지 확인해요.
3. `npx tsc`가 조용하면 해결이에요.

### `error TS1295: ECMAScript imports and exports cannot be written in a CommonJS file under 'verbatimModuleSyntax'.`
- 관련: [P2 Day 4](#/day/p2-d04), [P2 Day 6](#/day/p2-d06)

**원인:** `package.json`에 `"type": "module"`이 없어요. `export`만 쓴 파일은 `TS1287`로 나기도 해요.

**해결:**

1. `npm pkg set type=module`을 실행해요.
2. `package.json`에 `"type": "module"` 줄이 생겼는지 확인해요.
3. `npx tsc`를 다시 실행해 오류가 사라지면 해결이에요.

### `error TS2322: Type '"Chzzk"' is not assignable to type 'Platform'.` / `TS2820`
- 관련: [P2 Day 5](#/day/p2-d05)

**원인:** 리터럴 타입은 대소문자까지 같아야 해요. 비슷한 값이 있으면 `Did you mean '"chzzk"'?`가 붙어요(`TS2820`).

**해결:**

1. 오류가 가리키는 줄에서 `Did you mean` 뒤의 글자로 고쳐요.
2. 저장하고 `npx tsc`가 조용하면 해결이에요.

### `error TS18047: 'streamer.avatarUrl' is possibly 'null'.`
- 관련: [P2 Day 5](#/day/p2-d05)

**원인:** `string | null` 값을 `null` 확인 없이 `.length` 등으로 썼어요.

**해결:**

1. 값을 쓰기 전에 `if (값 !== null) { … }`로 확인해요.
2. 또는 `값 ?? '대신 쓸 글자'`, `값?.length`로 바꿔요.
3. `npx tsc`가 조용하면 해결이에요.

### `error TS2835: Relative import paths need explicit file extensions in ECMAScript imports…`
- 관련: [P2 Day 6](#/day/p2-d06)

**원인:** 연습 폴더(`nodenext` 방식)에서 `import` 경로 끝에 확장자(`.js`)를 쓰지 않았어요.

**해결:**

1. 오류의 `Did you mean './data.js'?`대로 `./data.js`로 고쳐요.
2. 저장하고 `npx tsc`가 조용하면 해결이에요.

### `error TS1484: 'Paged' is a type and must be imported using a type-only import…`
- 관련: [P2 Day 6](#/day/p2-d06)

**원인:** 타입(`interface`, `type`)을 일반 `import { … }`로 가져왔어요.

**해결:**

1. 해당 줄을 `import type { … } from '…';`로 고쳐요.
2. 값(함수, 배열)과 타입은 줄을 나눠 가져와요.
3. `npx tsc`가 조용하면 해결이에요.

### `Port 5173 is in use, trying another one...`
- 관련: [P2 Day 7](#/day/p2-d07)

**원인:** 다른 터미널이나 VS Code 창에서 개발 서버가 이미 5173번을 쓰고 있어요. Vite가 다음 번호(5174)로 켜 줬어요. 오류가 아니에요.

**해결:**

1. 터미널에 보이는 `Local:` 주소(5174 등)로 브라우저를 열어요.
2. 같은 프로젝트의 옛 서버를 끄려면 그 터미널을 클릭하고 `Ctrl + C`를 눌러요(`Terminate batch job (Y/N)?`가 나오면 `Y`).
3. 다시 `npm run dev`를 해서 `Local:`이 `5173`이면 해결이에요.

### `dotnet --version`이 8이나 9로 시작해요
- 관련: [P2 Day 9](#/day/p2-d09)

**원인:** 10 SDK가 설치되지 않았거나 `global.json`이 다른 버전을 고정했어요.

### `error CS0029` / `CS0165` / `CS1012` / `CS0163` / `CS8803` (C# 기본 문법)
- 관련: [P2 Day 10](#/day/p2-d10)

**원인:** 흔한 C# 컴파일 오류예요. `CS0029`는 글자를 숫자 변수에 넣었을 때, `CS0165`는 값 없는 변수를 읽었을 때, `CS1012`는 작은따옴표에 여러 글자를 넣었을 때, `CS0163`은 `switch` 문의 `case`에 `break;`가 없을 때, `CS8803`은 `enum` 선언 아래에 실행 코드를 썼을 때 나요.

**해결:**

1. 오류의 `(줄,칸)`이 가리키는 곳을 VS Code에서 찾아요.
2. 위 원인에 맞게 고쳐요: 타입과 값을 맞추고, 변수에 처음 값을 넣고, 여러 글자는 큰따옴표를 쓰고, `case` 끝에 `break;`를 더하고, `enum`은 파일 맨 아래로 옮겨요.
3. `dotnet run`이 통과하면 해결이에요.
