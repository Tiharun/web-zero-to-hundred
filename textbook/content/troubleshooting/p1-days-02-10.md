# P1 문제 해결 (Day 2~10)

### 내려받은 VS Code 설치 파일이 안 보여요
- 관련: [P1 Day 2](#/day/p1-d02)

**원인:** 브라우저가 파일을 `다운로드` 폴더에 저장하는데, 폴더가 OneDrive 안으로 옮겨져 있거나 내려받기가 끝나지 않았을 수 있어요. 그래서 파일 탐색기에서 찾으면 안 보일 때가 있어요.

**해결:**

1. 브라우저에서 `Ctrl + J`를 눌러 다운로드 목록을 열어요.
2. 목록 맨 위의 `VSCodeUserSetup-…` 항목이 "완료"인지 확인해요. 진행 중이면 끝날 때까지 기다려요.
3. 항목을 클릭하면 바로 실행돼요. 폴더 모양 아이콘(폴더에 표시)을 누르면 파일이 있는 폴더가 열려요.
4. 목록에 아무것도 없으면 `https://code.visualstudio.com/`에서 **Download for Windows** 버튼을 다시 눌러요.
5. 설치 마법사 첫 화면이 열리면 해결된 거예요.

### 파란 "Windows의 PC 보호" 창이나 "이 앱이 디바이스를 변경하도록 허용하시겠어요?" 창이 떠요
- 관련: [P1 Day 2](#/day/p1-d02)

**원인:** Windows는 내려받은 실행 파일을 처음 실행할 때 게시자를 확인하라고 알려 줘요. 처음 보는 프로그램이면 파란 경고(Microsoft Defender SmartScreen)가 뜨고, 설치할 때 사용자 계정 컨트롤(UAC) 창이 뜰 수도 있어요. 문구는 Windows 버전에 따라 조금 달라요.

**해결:**

1. 창에 쓰인 앱 이름이 Visual Studio Code인지, 게시자가 **Microsoft Corporation**인지 읽어요. 이 확인 없이 누르지 않는 습관이 중요해요.
2. 파란 경고 창이면 글자 **추가 정보**를 클릭하고, 새로 나타난 **실행** 버튼을 클릭해요. 게시자가 Microsoft가 아니거나 다른 사이트에서 받은 파일이면 실행하지 말고 지워요.
3. 사용자 계정 컨트롤 창이면 게시자를 확인하고 **예**를 클릭해요. User setup은 보통 이 창이 뜨지 않아요.
4. 설치 마법사의 사용권 계약 화면이 열리면 해결된 거예요.

### 설치할 때 관리자 암호를 물어요 (VSCodeSetup 파일을 받았어요)
- 관련: [P1 Day 2](#/day/p1-d02)

**원인:** 내려받은 파일 이름이 `VSCodeSetup-…`으로 시작하면 모든 사용자용으로 `Program Files`에 설치하는 System setup이에요. 이 방식은 관리자 권한이 필요해서 관리자 암호를 물어요. 이 교재는 관리자 권한이 필요 없는 User setup(`VSCodeUserSetup-…`)을 써요.

**해결:**

1. 암호를 묻는 창은 닫고, 설치 마법사도 취소해요.
2. 브라우저에서 `https://code.visualstudio.com/`을 열고 **Download for Windows** 버튼 대신 **Other platforms**(다른 플랫폼) 또는 다운로드 페이지의 Windows **User Installer**(x64)를 골라 내려받아요. 화면 이름은 버전에 따라 조금 달라요.
3. 내려받은 파일 이름이 `VSCodeUserSetup-`으로 시작하는지 확인하고 실행해요.
4. 관리자 암호 없이 사용권 계약 화면까지 가면 해결된 거예요.

### 한국어 팩을 설치했는데 메뉴가 영어예요
- 관련: [P1 Day 2](#/day/p1-d02)

**원인:** 한국어 팩은 설치한 뒤 VS Code를 다시 시작해야 적용돼요. 오른쪽 아래 알림의 **Change Language and Restart** 버튼을 놓쳤거나 알림이 사라졌을 수 있어요.

**해결:**

1. `Ctrl + Shift + P`를 눌러 명령 팔레트를 열어요.
2. `Configure Display Language`를 입력하고 `Enter`를 눌러요.
3. 언어 목록에서 `한국어`(`ko`)를 클릭해요. 목록에 없으면 확장 화면에서 Korean Language Pack이 설치(Installed)되어 있는지 확인해요.
4. 오른쪽 아래에 나오는 **Restart**(다시 시작) 버튼을 클릭해요.
5. 다시 열린 창의 메뉴가 `파일`, `편집`, `선택 영역`으로 시작하면 해결된 거예요.

### 창 위에 "제한 모드"(Restricted Mode)라고 나와요
- 관련: [P1 Day 2](#/day/p1-d02)

**원인:** 폴더를 처음 열 때 나온 신뢰 창에서 **아니요**를 눌렀거나 창을 닫았어요. VS Code는 모르는 폴더의 코드를 함부로 실행하지 않도록 제한 모드로 시작해요. 내가 만든 폴더는 신뢰해도 안전해요.

**해결:**

1. 편집기 맨 위의 제한 모드 안내 줄에서 **관리**(Manage) 버튼을 클릭해요. 안내 줄이 없으면 창 맨 아래 상태 표시줄의 **제한 모드** 글자를 클릭해요.
2. 열린 화면에서 **폴더 신뢰**(Trust Folder) 계열의 버튼을 클릭해요. 문구는 버전에 따라 조금 달라요.
3. 창 위쪽의 "제한 모드" 글자가 사라지면 해결된 거예요.

### 편집기 오른쪽 위에 Live Preview 아이콘이 안 보여요
- 관련: [P1 Day 2](#/day/p1-d02)

**원인:** 미리 보기 아이콘은 `.html` 파일 탭이 앞에 있을 때만 보여요. 폴더만 열려 있거나 다른 종류의 탭이 앞에 있을 수 있어요. Live Preview 확장 프로그램이 아직 설치되지 않았을 수도 있어요.

**해결:**

1. 탐색기에서 `hello.html`을 클릭해 탭을 앞으로 가져와요.
2. 오른쪽 위 모서리에 아이콘이 생겼는지 확인해요.
3. 그래도 없으면 `Ctrl + Shift + P`를 눌러 `Live Preview: Show Preview`를 입력해요. 목록에 이 이름이 하나도 없으면 확장 설치가 안 된 거예요. `Ctrl + Shift + X`로 확장 화면을 열어 **설치됨** 목록에 Live Preview가 있는지 확인하고, 없으면 5단계를 다시 해요.
4. 미리 보기 창이 열리면 해결된 거예요.

### 탐색기에 폴더가 없고 파일 하나만 열려요
- 관련: [P1 Day 2](#/day/p1-d02)

**원인:** **파일 → 파일 열기**로 `hello.html` 하나만 열었어요. 폴더가 아니라 파일을 연 상태라서 탐색기에 파일 목록이 안 보이고, Live Preview도 이 파일 하나만 다루기 어려워요.

**해결:**

1. 맨 위 메뉴 **파일 → 폴더 열기**를 클릭해요.
2. 주소 표시줄에 `C:\dev\hello`를 입력하고 `Enter`, 이어서 **폴더 선택**을 클릭해요.
3. 저장하지 않은 내용이 있다는 창이 뜨면 먼저 `Ctrl + S`로 저장해요.
4. 탐색기 맨 위에 `HELLO`가 보이고 그 아래에 파일 목록이 있으면 해결된 거예요.

### Windows 보안 경고 창(방화벽)이 떠서 허용하라고 해요
- 관련: [P1 Day 2](#/day/p1-d02)

**원인:** Live Preview가 내 컴퓨터 안에서 서버를 띄울 때, 환경에 따라 Windows 방화벽이 "이 앱의 네트워크 접근을 허용할까요?"를 물을 수 있어요. 대부분은 이 창이 뜨지 않아요(내 컴퓨터 안에서만 쓰는 서버라서 뜨지 않는 경우가 많을 것으로 보여요). 뜨는 조건과 문구는 실기로 확인하지 못했어요.

**해결:**

1. 창에 적힌 앱 이름이 Visual Studio Code(또는 Code, Node.js)이고 게시자가 Microsoft나 OpenJS Foundation인지 확인해요.
2. 허용할 네트워크 종류에서 **개인 네트워크**만 체크하고 **공용 네트워크**는 체크하지 않아요. 공용 네트워크는 카페 같은 공개된 와이파이라서 열면 안 돼요.
3. **액세스 허용**(Allow access)을 클릭해요. 허용하지 않아도 내 컴퓨터 안에서 보는 미리 보기는 보통 동작해요.
4. 미리 보기 창에 페이지가 보이면 해결된 거예요.

### Chrome이 계속 "기본 브라우저로 설정"을 물어요
- 관련: [P1 Day 2](#/day/p1-d02)

**원인:** Chrome은 기본 브라우저가 아니면 실행할 때마다 설정을 권해요. 오류가 아니에요.

### `!`를 쳐도 Emmet 제안이 안 떠요
- 관련: [P1 Day 3](#/day/p1-d03)

**원인:** Emmet은 VS Code가 파일을 HTML로 알아볼 때만 동작해요. 파일을 `.html`로 만들지 않았거나(아직 저장 전 새 파일), 한글 입력 상태라서 `!`를 다른 글자로 입력했을 수 있어요. 제안 목록이 떴다가 사라진 경우도 있어요.

**해결:**

1. 창 맨 아래 상태 표시줄 오른쪽에 `HTML`이라고 보이는지 확인해요. `일반 텍스트`(Plain Text)면 `index.html`로 저장하지 않은 파일이에요. 글자를 클릭해 **HTML**을 고르거나, 탐색기에서 `index.html`을 새로 만들어요.
2. `한/영` 키로 영어 입력 상태(작업 표시줄 오른쪽 아래 **A**)로 바꾸고 `!`를 다시 입력해요.
3. 제안 목록이 안 보이면 `Ctrl + Space`를 눌러 목록을 다시 열고, `!` 항목을 고르고 `Tab`을 눌러요.
4. `<!DOCTYPE html>`로 시작하는 뼈대가 생기면 해결된 거예요.

### index.html을 엉뚱한 폴더(C:\dev\hello)에 만들었어요
- 관련: [P1 Day 3](#/day/p1-d03)

**원인:** VS Code에 `hello` 폴더가 열려 있는 상태에서 새 파일을 만들면 그 폴더에 만들어져요. 탐색기 맨 위 이름이 `HELLO`이면 폴더를 잘못 연 거예요.

**해결:**

1. VS Code 탐색기 맨 위 이름을 읽어요. `MY-CREATOR-SITE`가 아니라 `HELLO`면 잘못 열린 거예요.
2. **파일 → 폴더 열기**를 클릭해 `C:\dev\my-creator-site`를 열어요.
3. 파일 탐색기에서 `C:\dev\hello\index.html`을 한 번 클릭하고 `Delete` 키로 지워요(휴지통으로 가요). 이 파일은 오늘 쓰지 않아요.
4. `my-creator-site` 폴더에서 4단계부터 다시 해요. 탐색기에 `MY-CREATOR-SITE` 아래 `index.html`이 보이면 해결된 거예요.

### 큰 제목 아래의 글씨까지 전부 크게 보여요
- 관련: [P1 Day 3](#/day/p1-d03)

**원인:** 제목이나 문단의 닫는 태그 `</h1>`을 빠뜨렸거나 `/`를 빠뜨려서 `<h1>`으로 썼어요. 브라우저가 "제목이 아직 안 끝났구나" 하고 아래 글까지 모두 제목으로 보여 줘요.

**해결:**

1. 큰 글씨가 시작되는 줄부터 위로 거슬러 올라가며, 열었는데 닫지 않은 태그를 찾아요.
2. 그 줄 끝에 `</h1>`처럼 닫는 태그를 써요. `/`가 빠져 `<h1>`이라고 되어 있다면 `<h1>`을 `</h1>`로 고쳐요.
3. `Ctrl + S`로 저장하고 미리 보기를 확인해요.
4. 제목만 크고 아래 글은 보통 크기로 돌아오면 해결된 거예요.

### Edge가 "이 페이지를 번역하시겠습니까?"라고 물어요
- 관련: [P1 Day 3](#/day/p1-d03)

**원인:** `<html lang="en">`이 그대로 있어서 브라우저가 이 문서를 영어로 알고 있어요. 한글 문서인데 영어라고 적혀 있으니 번역을 권해요.

**해결:**

1. `index.html`의 `<html lang="en">`을 `<html lang="ko">`로 바꿔요.
2. `Ctrl + S`로 저장하고, 브라우저에서 `F5`를 눌러 새로 고침해요.
3. 번역 제안이 더 뜨지 않으면 해결된 거예요.

### `</h1></h1>`처럼 닫는 태그가 두 개가 돼요
- 관련: [P1 Day 3](#/day/p1-d03)

**원인:** VS Code는 `<h1>`을 입력하고 `>`를 치면 닫는 태그 `</h1>`을 자동으로 만들어 줘요. 이걸 모르고 닫는 태그를 직접 한 번 더 입력하면 겹쳐요.

**해결:**

1. 줄 끝에 닫는 태그가 두 개 붙은 곳을 찾아요.
2. 하나를 지워서 `<h1>안녕하세요</h1>`처럼 한 번만 남겨요.
3. 앞으로는 여는 태그를 입력한 직후 글을 쓰고 `End` 키로 닫는 태그 뒤로 빠져나가요.
4. 줄에 닫는 태그가 하나만 있으면 해결된 거예요.

### Tab Size를 2로 바꿨는데 이미 있는 줄은 4칸 그대로예요
- 관련: [P1 Day 3](#/day/p1-d03)

**원인:** 설정은 앞으로 만드는 들여쓰기에만 적용돼요. 이미 입력된 줄은 그대로 있어요. Emmet으로 뼈대를 만든 뒤에 설정을 바꿨다면 뼈대는 4칸이에요. 화면 결과는 달라지지 않지만 교재 코드와 모양이 달라요.

**해결:**

1. 파일 전체를 지우고 4단계에서 `!` + `Tab`으로 뼈대를 다시 만들면 2칸으로 만들어져요.
2. 또는 맨 아래 상태 표시줄의 `공백: 4`를 클릭하고 **공백으로 들여쓰기 변환**(Convert Indentation to Spaces) 계열 항목을 골라요. 이름은 버전에 따라 조금 다를 수 있어요.
3. 줄 앞 칸 수가 달라도 화면은 같아요. 교재 코드와 똑같이 맞추지 않아도 괜찮아요.

### 링크를 눌렀더니 파일을 찾을 수 없다고 나와요 (ERR_FILE_NOT_FOUND)
- 관련: [P1 Day 4](#/day/p1-d04)

**원인:** 링크가 가리키는 파일이 그 폴더에 없어요. 가장 흔한 이유는 세 가지예요. ① `href`의 철자나 `.html`을 틀렸어요. ② 아직 만들지 않은 파일이에요. ③ 파일 이름이 `contact copy.html`처럼 달라요. 더블클릭한 페이지(`file://`)에서는 브라우저가 `ERR_FILE_NOT_FOUND`라는 오류 코드와 함께 "이 파일을 찾을 수 없음" 같은 안내를 보여 줘요(문구는 브라우저 버전에 따라 달라요).

**해결:**

1. 누른 링크의 `href` 값을 읽어요. 예: `href="contents.html"`.
2. VS Code 탐색기에서 같은 이름의 파일이 있는지 봐요. 철자, 하이픈, `.html`을 한 글자씩 비교해요.
3. 파일이 없으면 만들고, 이름이 다르면 파일을 클릭해 `F2`로 이름을 고쳐요(또는 `href`를 파일 이름에 맞춰요).
4. 저장하고 미리 보기를 새로 고쳐서 링크를 다시 눌러요. 페이지가 열리면 해결된 거예요.

### 복사한 파일 이름이 index copy.html로 남아 있어요
- 관련: [P1 Day 4](#/day/p1-d04)

**원인:** VS Code에서 파일을 복사해서 붙여넣으면 이름 뒤에 ` copy`가 자동으로 붙어요. 이름을 바꾸지 않으면 그 이름 그대로 파일이 되고, 메뉴 링크(`index.html`)는 이 파일을 찾지 못해요. 이름에 공백이 있는 것도 문제예요.

**해결:**

1. 탐색기에서 `index copy.html`을 클릭해요.
2. `F2`(노트북은 `Fn + F2`)를 눌러요. 이름 앞부분만 선택된 상태에서 새 이름을 입력해요. 예: `schedule`. 확장자 `.html`은 그대로 남아요.
3. `Enter`를 눌러 확정해요. 파일 이름에 공백이 없는지 확인해요.
4. 탐색기에 의도한 이름의 파일이 보이면 해결된 거예요.

### 링크가 깨지거나 아래 글이 이상하게 사라져요 (따옴표를 하나만 닫았어요)
- 관련: [P1 Day 4](#/day/p1-d04)

**원인:** `<a href="about.html>소개</a>`처럼 `href`의 닫는 따옴표를 빠뜨리면, 브라우저는 다음 따옴표가 나올 때까지를 모두 `href` 값으로 읽어요. 그래서 링크가 엉뚱한 곳으로 가거나 아래 글이 화면에서 사라져요. VS Code가 따옴표를 자동으로 닫아 주는데, 직접 한 번 더 입력하면 어긋나기도 해요.

**해결:**

1. 코드에서 `href="` 뒤 값 끝에 닫는 따옴표 `"`가 있는지 한 줄씩 확인해요. VS Code는 짝이 맞지 않으면 그 뒤 글자 색이 달라져서 알려 줘요.
2. 빠진 곳에 `"`를 넣어 `<a href="about.html">소개</a>`처럼 고쳐요.
3. 저장하고 새로 고침해요. 사라졌던 글이 보이고 링크가 열리면 해결된 거예요.

### 링크에 `\`나 `C:\`를 썼더니 열리지 않아요 (한글·공백 파일 이름도 포함)
- 관련: [P1 Day 4](#/day/p1-d04)

**원인:** 링크 주소에서 폴더를 가르는 기호는 `/`예요. `\`는 Windows 파일 경로에만 써요. 또 `C:\dev\…`처럼 내 컴퓨터 전체 경로를 쓰면 인터넷에 올린 뒤에는 열리지 않아요. 파일 이름에 한글이나 공백이 있으면(`소개.html`, `my page.html`) 주소가 `%EC%86%8C…`, `my%20page.html` 같은 기호로 바뀌어 읽기 어렵고 실수하기 쉬워요.

**해결:**

1. `href` 값에서 `C:\`와 `\`를 모두 지워요. 같은 폴더의 파일이면 `href="about.html"`처럼 파일 이름만 써요.
2. 파일 이름에 한글이나 공백이 있으면 탐색기에서 `F2`로 영어 소문자·숫자·하이픈 이름으로 바꾸고, `href`도 같이 고쳐요.
3. 저장하고 링크를 눌러요. 페이지가 열리면 해결된 거예요.

### profile.svg 코드를 넣었는데 그림 대신 글자(코드)가 보여요

2. SVG 코드가 `index.html` 안에 들어가 있지 않은지 확인해요. 들어가 있으면 그 줄들을 지워요.
3. `index.html`에 `<img src="images/profile.svg" alt="헤드셋을 쓴 곰 캐릭터, 달빛곰" width="240" height="240">`이 한 줄 있는지 확인해요.

### ../ 개수를 세다가 틀렸어요
- 관련: [P1 Day 5](#/day/p1-d05)

**원인:** `../`는 한 번 쓸 때마다 폴더가 한 칸씩 위로 올라가요. 올라가는 칸 수를 하나 틀리면 엉뚱한 폴더를 가리켜요. 기준은 "지금 이 HTML 파일이 있는 폴더"예요.

**해결:**

1. 지금 파일이 있는 폴더를 쓰고(`C:\dev\hello\pages`), 가려는 파일이 있는 폴더(`C:\dev\my-creator-site\images`)를 써요.
2. 두 폴더의 공통 폴더(`C:\dev`)까지 몇 칸 올라가야 하는지 세요. 이 예에서는 `pages` → `hello` → `dev`, 두 칸이에요. 그래서 `../../`예요.
3. 공통 폴더에서 목표 파일까지 내려가는 이름을 이어 써요: `../../my-creator-site/images/profile.svg`.
4. 저장하고 더블클릭으로 열어요. 그림이 보이면 해결된 거예요.

### F12를 눌러도 개발자 도구가 안 열려요
- 관련: [P1 Day 6](#/day/p1-d06)

**원인:** 이유는 세 가지예요. ① 노트북은 `F12`가 다른 기능(음량 등)에 먼저 배정되어 있어요. ② 열린 곳이 VS Code의 미리 보기 창이에요. 이 창은 브라우저가 아니라서 개발자 도구가 없어요. ③ 브라우저 창이 아니라 다른 앱이 앞에 있어요. Edge는 처음 `F12`를 누를 때 개발자 도구를 열 것인지 묻는 창이 뜰 수 있어요(문구는 버전에 따라 달라요).

**해결:**

1. 브라우저(Edge 또는 Chrome) 창을 클릭해서 앞으로 가져와요. VS Code 안이 아니라 `index.html`을 더블클릭해서 연 브라우저 탭이어야 해요.
2. `Fn + F12`를 눌러 봐요. 또는 `Ctrl + Shift + I`를 눌러요.
3. 그래도 안 되면 페이지의 빈 곳을 오른쪽 클릭하고 **검사**를 클릭해요.
4. 개발자 도구가 열려 Elements 목록이 보이면 해결된 거예요.

### 붙여 넣었더니 구조가 꼬이고 메뉴나 글이 이상한 곳에 나와요
- 관련: [P1 Day 6](#/day/p1-d06)

**원인:** 붙여 넣다가 닫는 태그(`</header>`, `</section>`, `</main>` 등)를 빠뜨렸거나 두 번 붙여 넣었을 수 있어요. 브라우저는 닫는 태그가 없으면 아래 내용을 모두 그 요소 안에 넣어서 보여 줘요.

**해결:**

5. Elements에서 `header`, `main`, `footer`가 `body` 바로 아래에 나란히 있으면 해결된 거예요.

### 개발자 도구가 영어로 나와요

2. 한국어로 바꾸고 싶다면 개발자 도구 오른쪽 위 톱니바퀴(설정)에서 언어 항목을 고르고 다시 시작해요. 이름은 버전에 따라 조금 달라요.

3. 새로 고침해도 고친 글자가 남아 있으면 해결된 거예요.

### 바닥글에 &copy가 그대로 보이거나 ©가 안 나와요

2. `&`로 시작하고 `;`로 끝나는지 확인하고 빠진 `;`를 넣어요.
3. 저장하고 새로 고침해요. ©가 보이면 해결된 거예요.

```powershell
git config --global core.editor "code --wait"
```

```powershell
git config --global user.name "달빛곰"
```

3. `[main (root-commit) …]` 줄이 나오면 해결된 거예요.

### fatal: not a git repository (or any of the parent directories): .git
- 관련: [P1 Day 7](#/day/p1-d07)

```powershell
cd C:\dev\my-creator-site
```

3. 위치가 맞는데도 오류면 `git init`을 한 번 실행해요. `Initialized empty Git repository`가 나와요.

### error: src refspec main does not match any
- 관련: [P1 Day 7](#/day/p1-d07)

**원인:** 푸시하려는 `main` 브랜치에 커밋이 하나도 없어요. `git commit`을 하기 전에 `git push`를 했거나, 커밋이 실패했거나, 브랜치 이름이 `main`이 아닐 때 나와요.

```text
error: src refspec main does not match any
error: failed to push some refs to 'https://github.com/moonbear-dev/my-creator-site.git'
```

**해결:**

1. `git log --oneline`을 입력해요. `fatal: your current branch 'main' does not have any commits yet`가 나오면 커밋이 없는 거예요.
2. `git add .`를 실행하고 `git commit -m "Day 1~6: 첫 페이지들"`을 실행해요.
3. 브랜치 이름이 다르면 `git branch -M main`을 실행해요.
4. 다시 `git push -u origin main`을 입력해요.
5. `* [new branch] main -> main` 줄이 나오면 해결된 거예요.

### error: remote origin already exists.
- 관련: [P1 Day 7](#/day/p1-d07)

**원인:** `git remote add origin …`을 이미 한 번 했어요. 같은 이름 `origin`을 두 번 만들 수 없어요. 처음 입력한 주소가 틀렸을 때도 이 오류가 나와요.

**해결:**

1. 연결된 주소를 확인해요.

```powershell
git remote -v
```

예상 출력(주소는 내 아이디에 따라 달라요):

```text
origin	https://github.com/moonbear-dev/my-creator-site.git (fetch)
origin	https://github.com/moonbear-dev/my-creator-site.git (push)
```

2. 주소가 맞으면 그대로 다음 단계로 가요.
3. 틀렸다면 아래 명령으로 `origin`의 주소를 바꿔요. 주소는 내 저장소 주소로 바꿔요.

```powershell
git remote set-url origin https://github.com/moonbear-dev/my-creator-site.git
```

4. `git remote -v`의 주소가 내 저장소와 같으면 해결된 거예요.

### ! [rejected] main -> main (fetch first)
- 관련: [P1 Day 7](#/day/p1-d07)

**원인:** GitHub에서 저장소를 만들 때 **Add a README file**을 체크해서, GitHub 쪽에 이미 내 컴퓨터에 없는 기록이 있어요. Git은 남의 기록을 덮어쓰지 않으려고 푸시를 거절해요. 문구와 안내(`hint:`)는 Git 버전에 따라 조금 달라요.

```text
To https://github.com/moonbear-dev/my-creator-site.git
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/moonbear-dev/my-creator-site.git'
hint: Updates were rejected because the remote contains work that you do not
hint: have locally. This is usually caused by another repository pushing to
hint: the same ref. If you want to integrate the remote changes, use
hint: 'git pull' before pushing again.
hint: See the 'Note about fast-forwards' in 'git push --help' for details.
```

**해결:** 오늘은 가장 쉬운 방법으로, 비어 있는 저장소로 다시 만들어요. 내 컴퓨터의 파일과 기록은 지워지지 않아요.

1. 브라우저에서 GitHub 저장소 페이지의 **Settings**를 클릭해요.
2. 맨 아래쪽 **Danger Zone**(위험 구역)에서 **Delete this repository**를 클릭하고, 화면 안내대로 저장소 이름을 입력해 삭제해요. 메뉴 이름은 바뀔 수 있어요.
3. 5단계처럼 `my-creator-site` 저장소를 다시 만들어요. 이번에는 **Add a README file**을 체크하지 않아요.
4. 터미널에서 `git push -u origin main`을 다시 입력해요.
5. ` * [new branch]      main -> main` 줄이 나오면 해결된 거예요.

### 푸시할 때 로그인 창이 안 뜨거나 다른 계정으로 로그인돼요
- 관련: [P1 Day 7](#/day/p1-d07)

**원인:** 처음 푸시할 때 Git Credential Manager가 브라우저로 로그인을 요청해요. 팝업이 다른 창 뒤에 숨어 있거나, 브라우저가 이미 다른 GitHub 계정으로 로그인되어 있으면 그 계정으로 인증돼요. 로그인 창의 모양은 버전에 따라 달라요(실기 확인은 못 했어요).

**해결:**

1. 작업 표시줄에서 다른 창 뒤에 숨은 로그인 창이나 브라우저 창을 찾아요.
2. 브라우저에서 GitHub의 오른쪽 위 프로필을 눌러 지금 로그인된 계정이 이 저장소 주인인지 확인해요. 다르면 로그아웃하고 올바른 계정으로 로그인해요.
3. 인증 창에서 **Authorize**(허용)를 클릭해요.
4. `git push -u origin main`을 다시 입력해요.
5. 오류 없이 ` * [new branch]` 줄이 나오면 해결된 거예요.

### GitHub 인증 메일이 안 와요
- 관련: [P1 Day 7](#/day/p1-d07)

**원인:** 인증 코드 메일이 스팸 메일함으로 갔거나, 이메일 주소를 잘못 입력했거나, 메일이 도착하기까지 몇 분 걸리는 경우예요.

3. 주소를 잘못 입력했다면 가입 화면에서 이메일을 고치고 다시 보내요.
4. 코드가 도착해 입력 칸에 붙여 넣고 가입 화면이 넘어가면 해결된 거예요.

### git commit만 쳤더니 VS Code에 COMMIT_EDITMSG 탭이 열렸어요
- 관련: [P1 Day 7](#/day/p1-d07)

**원인:** `-m "메시지"` 없이 `git commit`만 입력하면 Git이 커밋 메시지를 쓰라고 편집기(VS Code)를 열어요. 오류가 아니에요.

### warning: in the working copy of '…', LF will be replaced by CRLF the next time Git touches it
- 관련: [P1 Day 7](#/day/p1-d07)

**원인:** Windows는 줄바꿈을 CRLF로, Git의 기록은 LF로 저장해요. Git for Windows의 기본 설정(Checkout Windows-style, commit Unix-style)에서는 `git add`를 할 때 줄바꿈이 LF뿐인 파일에 대해 "다음에 Git이 파일을 만질 때 Windows 방식으로 바뀔 거예요"라고 알려 줘요.

```text
warning: in the working copy of 'images/logo.svg', LF will be replaced by CRLF the next time Git touches it
```

파일 이름은 사람마다 달라요.

**해결:** 오류가 아니라 안내라서 무시해도 돼요.

1. 이어서 `git status`를 입력해 파일이 `new file:` 또는 `modified:`로 보이는지 확인해요.
2. 커밋과 푸시를 그대로 계속해요.
3. 커밋이 정상적으로 만들어지면 문제없는 거예요. 줄바꿈이 달라도 HTML·CSS·JavaScript는 똑같이 동작해요.

### git add. 처럼 띄어쓰기를 빠뜨렸어요
- 관련: [P1 Day 7](#/day/p1-d07)

**원인:** `git add`와 `.` 사이에 빈칸이 있어야 해요. 붙여 쓰면 Git이 `add.`라는 명령을 찾아요.

```text
git: 'add.' is not a git command. See 'git --help'.

The most similar command is
	add
```

**해결:**

1. `git add .`처럼 `add`와 점 사이에 빈칸 한 칸을 넣어 다시 입력해요.
2. `git status`에서 `Changes to be committed` 목록이 보이면 해결된 거예요.

### .git 폴더를 실수로 지웠어요
- 관련: [P1 Day 7](#/day/p1-d07)

**원인:** `.git` 숨김 폴더에 모든 기록이 있어서, 지우면 내 컴퓨터의 커밋 기록이 모두 사라져요. 파일 자체는 그대로 남아 있어요. GitHub에 올려 둔 기록은 남아 있어요.

**해결:**

1. 휴지통에서 `.git` 폴더를 찾아 오른쪽 클릭 → **복원**을 클릭해요. 폴더를 바로 지웠다면 가장 쉽게 돌아올 수 있어요.
2. 복원할 수 없다면 `C:\dev\my-creator-site`에서 6~7단계(`git init`부터)를 다시 해요. 단, GitHub 저장소에 이미 기록이 있으면 푸시가 거절될 수 있어요. 그땐 위의 `! [rejected] main -> main (fetch first)` 항목처럼 저장소를 새로 만들어요.
3. `git status`가 `On branch main`을 보여 주면 해결된 거예요.

### YouTube 칸에 오류 문구가 나오거나 영상이 재생되지 않아요
- 관련: [P1 Day 8](#/day/p1-d08)

**해결:**

2. 더블클릭으로 열었다면 VS Code에서 `index.html`을 Live Preview로 열어 다시 확인해요.
3. 그래도 안 되면 YouTube에서 같은 영상을 직접 열어 재생되는지 확인하고, 영상의 **공유 → 퍼가기** 메뉴가 열리는지 봐요. 퍼가기가 막힌 영상이면 다른 영상 ID로 바꿔요.
4. Day 14에서 만들 배포 주소에서도 확인해 볼 수 있어요.
5. 영상이 재생되면 해결된 거예요. 재생이 안 돼도 이후 Day를 따라가는 데는 문제없어요.

3. 영상이 보이면 해결된 거예요.

### 보내기를 눌렀더니 주소가 바뀌고 입력한 칸이 모두 비워져요

3. 칸이 다시 비어 있는 폼이 보이면 정상이에요.

### 글자를 눌러도 입력 칸에 커서가 안 들어가요

**해결:**

1. 칸마다 `<label for="name">`과 `<input id="name" …>`의 값이 같은지 한 쌍씩 비교해요.
2. 다르면 `input`의 `id`를 `label`의 `for`에 맞춰요(또는 반대로).
3. 저장하고 새로 고침한 뒤, 글자를 눌러 커서가 들어가면 해결된 거예요.

### CSS가 전혀 안 먹혀요 (글꼴·색이 그대로예요)
- 관련: [P1 Day 9](#/day/p1-d09)

**원인:** 브라우저가 `style.css`를 찾지 못했거나 읽었는데 규칙이 틀렸어요. 가장 흔한 이유는 다섯 가지예요. ① `<link>`의 `href` 경로 오타. ② `rel="stylesheet"`를 빠뜨렸어요. ③ `style.css`가 `css` 폴더 밖에 있어요. ④ 파일 이름이 `style.css.css`나 `style.css.txt`예요. ⑤ 폴더 이름이 `Css`처럼 대문자예요(인터넷에 올린 뒤에 깨져요).

**해결:**

1. VS Code 탐색기에서 `MY-CREATOR-SITE` 아래 `css` 폴더와 그 안의 `style.css`를 확인해요. 파일 이름이 다르면 `F2`로 고쳐요.
2. HTML의 `<link rel="stylesheet" href="css/style.css">` 줄이 한 글자도 다르지 않은지 비교해요.
3. 저장하고 `Ctrl + F5`로 강력 새로 고침해요.
4. 개발자 도구 Elements에서 `<head>`를 펼쳐 `link` 줄을 클릭하고, 오른쪽 위에 오류 표시가 없는지 확인해요.
5. 글꼴과 링크 색이 바뀌면 해결된 거예요.

### 일부 규칙만 먹고 나머지는 안 먹어요
- 관련: [P1 Day 9](#/day/p1-d09)

**원인:** CSS는 중괄호 `{ }`나 세미콜론 `;`을 빠뜨리면 그 규칙 이후가 무시되거나 엉뚱하게 해석돼요. VS Code는 이런 곳에 빨간 물결 밑줄을 그어 알려 줘요.

**해결:**

1. `style.css`에서 빨간 물결 밑줄이 있는 곳에 마우스를 올려 메시지를 읽어요.
2. 규칙마다 `{`가 하나, `}`가 하나인지, 속성 줄마다 끝에 `;`이 있는지 확인해요.
3. 고치고 저장한 뒤 `Ctrl + F5`로 새로 고침해요.
4. 모든 규칙이 적용되면 해결된 거예요.

### 한글 입력 상태로 쳤더니 : ; { } 모양이 이상해요
- 관련: [P1 Day 9](#/day/p1-d09)

**원인:** 한글 입력 상태에서 기호를 치면 전각 문자(`：`, `；`, `｛` 같은 폭이 넓은 기호)가 입력될 수 있어요. 모양이 비슷해도 CSS는 알아보지 못해서 규칙이 무시돼요.

**해결:**

2. 이상하게 넓어 보이는 `：`, `；`, `｛`, `｝`를 지우고 다시 입력해요. VS Code가 이상한 문자에 노란 상자로 표시해 주기도 해요.
3. 저장하고 새로 고침해서 규칙이 적용되면 해결된 거예요.

### class="site-header"에 점을 붙였더니 안 먹어요
- 관련: [P1 Day 9](#/day/p1-d09)

**원인:** HTML의 `class` 값에는 점을 쓰지 않아요. 점(`.`)은 CSS 선택자에서 "클래스를 고른다"는 표시예요. `class=".site-header"`라고 쓰면 이름이 `.site-header`인 클래스가 되어 CSS의 `.site-header`와 맞지 않아요.

**해결:**

1. HTML에서 `class="site-header"`처럼 점 없이 써요.
2. CSS에서는 `.site-header { … }`처럼 앞에 점을 써요.
3. 저장하고 새로 고침해요. 머리글 배경이 연보라가 되면 해결된 거예요.
