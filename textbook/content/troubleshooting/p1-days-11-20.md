# P1 문제 해결 (Day 11~20)

### 메뉴가 세로로 그대로예요 (display: flex가 안 먹어요)
- 관련: [P1 Day 11](#/day/p1-d11)

**원인:** `display: flex;`는 **자식들을 줄 세울 부모**에 써야 해요. 링크(`a`)나 `li`에 써도 그 안쪽만 바뀌어서 메뉴 모양은 그대로예요. 메뉴는 `ul`(`.menu-list`)에, 로고와 메뉴 한 줄은 `.header-inner`에 써요.

**해결:**

1. `style.css`에서 `.menu-list`와 `.header-inner` 규칙 안에 `display: flex;`가 있는지 확인해요.
2. 규칙 이름의 점(`.`)과 HTML의 class 이름 철자가 같은지 비교해요(`menu-list`, `header-inner`).
3. `Ctrl + S`로 저장하고 브라우저에서 `Ctrl + F5`를 눌러요. 메뉴가 가로로 늘어서면 해결이에요.

### 메뉴 앞에 점(•)이 남아 있거나 왼쪽에 이상한 여백이 있어요
- 관련: [P1 Day 11](#/day/p1-d11)

**원인:** `ul`은 브라우저가 앞 점과 왼쪽 들여쓰기(`padding`)를 기본으로 넣어요. `list-style: none;`은 점을, `padding: 0;`은 들여쓰기를 없애요.

**해결:**

1. `.menu-list { … }` 규칙에 `list-style: none;`, `margin: 0;`, `padding: 0;` 세 줄이 있는지 확인해요.
2. 세미콜론(`;`)이 빠졌거나 한글 입력 상태로 쳐서 `；`(전각)로 들어가진 않았는지 봐요.
3. 저장하고 새로 고침해서 점이 사라지면 해결이에요.

### 모든 페이지에서 홈 메뉴만 강조돼요
- 관련: [P1 Day 11](#/day/p1-d11)

**원인:** 머리글을 복사하면서 `aria-current="page"`까지 같이 복사했어요. 이 속성은 페이지마다 자기 메뉴에만 붙어야 해요.

**해결:**

1. `about.html`처럼 홈이 아닌 페이지를 열고, `홈` 줄에서 ` aria-current="page"`를 지워요.
2. 그 페이지의 자기 메뉴(소개 페이지라면 `소개`) 링크에 ` aria-current="page"`를 써 넣어요.
3. `Ctrl + Shift + F`로 `aria-current`를 검색해요. 결과는 `style.css` 1줄과 페이지 5줄(합계 6줄)이에요. 페이지 5줄이 서로 다른 글자인지 확인해요.

### 현재 페이지 메뉴가 강조되지 않아요 (속성 선택자)
- 관련: [P1 Day 11](#/day/p1-d11)

**원인:** 속성 선택자는 따옴표와 대괄호가 짝이 맞아야 해요. `a[aria-current=page"]`처럼 따옴표 하나가 빠지거나 `]`가 없으면 그 규칙은 통째로 무시돼요.

**해결:**

1. `.menu-list a[aria-current="page"]`를 6단계의 블록과 글자 하나씩 비교해요. 대괄호 `[ ]`와 큰따옴표 `" "`가 짝을 이루는지 봐요.
2. HTML의 `aria-current="page"`에도 오타(`aria-curent`)가 없는지 봐요.
3. 저장하고 새로 고침해서 보라색 알약이 나타나면 해결이에요.

### 버튼 글꼴만 달라 보여요
- 관련: [P1 Day 11](#/day/p1-d11)

**원인:** `<button>`은 브라우저가 따로 정한 작은 글꼴을 써요. `font: inherit;`가 빠지면 `보내기` 버튼 글자만 다르게 보여요.

**해결:**

1. `button, .button { … }` 규칙 안에 `font: inherit;` 줄을 넣어요.
2. 저장하고 문의 페이지를 새로 고침해서 `보내기` 글자가 주변 글자와 같은 글꼴이면 해결이에요.

### 메뉴가 오른쪽으로 가지 않아요
- 관련: [P1 Day 11](#/day/p1-d11)

**원인:** `margin-left: auto;`를 `ul`(`.menu-list`)에 줬어요. 이 요령은 Flexbox 줄 안에서 **로고 옆의 자식**에 써야 하는데, 그 자식은 `nav`(`.site-nav`)예요. `ul`은 `nav` 안에 있어서 효과가 없어요.

**해결:**

1. `.menu-list`에서 `margin-left: auto;`를 지워요(`margin: 0;`은 그대로 둬요).
2. `.site-nav { margin-left: auto; }` 규칙이 있는지 확인해요.
3. 저장하고 새로 고침해서 메뉴가 오른쪽 끝에 붙으면 해결이에요.

### 카드가 계속 세로로만 쌓여요 (칸이 안 나뉘어요)
- 관련: [P1 Day 12](#/day/p1-d12)

**원인:** `grid-template-columns`가 적용되지 않았어요. 흔한 이유는 세 가지예요. ① `class="card-grid"`를 `div`가 아니라 `article`에 붙였거나 `div`로 감싸지 않았어요. ② CSS의 `repeat(auto-fit, minmax(240px, 1fr))`에서 쉼표나 괄호가 빠졌어요. ③ 규칙 이름이 `.card-grid`가 아니에요.

**해결:**

1. `index.html`에서 `<div class="card-grid">`가 세 `article`을 모두 감싸는지 확인해요.
2. `style.css`의 `repeat(auto-fit, minmax(240px, 1fr))`를 3단계 블록과 글자 하나씩 비교해요. 쉼표 두 개(`auto-fit,` 뒤, `240px,` 뒤)와 닫는 괄호 두 개가 있어야 해요.
3. 저장하고 `Ctrl + F5`로 새로 고침해서 카드가 가로로 나란히 놓이면 해결이에요.

### 그림이 카드 밖으로 튀어나오거나 모서리가 각져 보여요
- 관련: [P1 Day 12](#/day/p1-d12)

**원인:** `.card img { width: 100%; }`나 `.card`의 `overflow: hidden;`이 빠졌어요. 그림이 원래 크기(320px) 그대로라 카드 폭과 달라지고, 둥근 모서리 밖으로 나온 부분이 잘리지 않아요.

**해결:**

1. `.card { … }` 규칙 안에 `overflow: hidden;`이 있는지 확인해요.
2. `.card img { display: block; width: 100%; }` 규칙이 있는지 확인해요.
3. 저장하고 새로 고침해서 그림이 카드 폭을 꽉 채우고 위쪽 모서리가 둥글면 해결이에요.

### 썸네일이 안 보여요 (깨진 그림 아이콘)
- 관련: [P1 Day 12](#/day/p1-d12)

**원인:** 파일 이름이나 경로가 달라요. 가장 흔한 실수는 `thumb_game.svg`처럼 밑줄(`_`)로 만들었거나, 파일이 `images` 폴더가 아닌 곳에 저장된 경우예요. HTML의 `src="images/thumb-game.svg"`와 실제 파일 이름은 대소문자와 하이픈까지 같아야 해요.

**해결:**

1. VS Code 탐색기에서 `images` 폴더 안의 파일 이름이 `thumb-game.svg`, `thumb-talk.svg`, `thumb-music.svg`인지 확인해요.
2. 이름이 다르면 파일을 오른쪽 클릭 → **이름 바꾸기**로 고치거나, 닫혀 있는 파일이라면 탐색기에서 `F2`로 바꿔요.
3. `index.html`의 `src` 값도 같은 이름인지 확인하고, 새로 고침해서 그림이 보이면 해결이에요.

### 카드마다 높이가 달라 보여요
- 관련: [P1 Day 12](#/day/p1-d12)

**원인:** 정상이에요. 카드 안 글이 길면 카드가 길어져요. 한 줄에 있는 카드들은 Grid가 같은 높이로 맞춰 주지만, 줄이 다르면 높이가 달라도 괜찮아요.

**해결:**

1. 같은 줄의 카드 높이가 서로 같다면 정상이에요.
2. 줄마다 높이가 달라 거슬린다면 설명 글의 길이를 비슷하게 맞춰 봐요.

### 개발자 도구에서 grid 배지가 안 보여요
- 관련: [P1 Day 12](#/day/p1-d12)

**원인:** `display: grid;`가 켜진 요소 줄에만 배지가 붙어요. 카드 하나(`article`)나 `.card-body` 줄에서는 안 보여요. 또 Live Preview 미리 보기 창에는 개발자 도구가 없어요.

**해결:**

1. Edge나 Chrome에서 페이지를 열고 `F12`를 눌러 **Elements**를 열어요.
2. 코드 목록에서 `<div class="card-grid">` 줄을 찾아요(`Ctrl + F`로 `card-grid`를 검색해도 돼요).
3. 그 줄 오른쪽 `grid` 배지를 눌러요. 점선이 보이면 해결이에요.

### 미디어 쿼리가 안 먹어요
- 관련: [P1 Day 13](#/day/p1-d13)

**원인:** 흔한 이유는 네 가지예요. ① `@media (min-width: 768px) {`의 괄호나 중괄호 짝이 맞지 않아요. ② `min-width: 768`처럼 단위 `px`가 빠졌어요. ③ 미디어 쿼리 아래에 같은 선택자의 규칙이 또 있어서 덮어써요. ④ 미디어 쿼리가 파일 맨 끝이 아니에요.

**해결:**

1. `style.css`에서 `@media`로 시작하는 줄을 6단계의 블록과 글자 하나씩 비교해요. 괄호 `( )`와 중괄호 `{ }`는 모두 짝이 맞아야 해요.
2. 숫자 뒤에 `px`가 있는지 확인해요(`768px`).
3. 미디어 쿼리 블록이 파일 맨 아래에 있는지, 그 아래에 같은 규칙이 또 없는지 확인해요.
4. 저장하고 `Ctrl + F5`로 새로 고침해서 모양이 바뀌면 해결이에요.

### 기기 모드를 켰는데 모양이 그대로예요
- 관련: [P1 Day 13](#/day/p1-d13)

**원인:** CSS를 고친 뒤 기기 모드 화면을 새로 고치지 않았거나, 기기 모드의 폭이 768 이상이에요. 또 같은 단축키(`Ctrl + Shift + M`)를 한 번 더 누르면 기기 모드가 꺼져요.

**해결:**

1. 개발자 도구 위쪽의 폭 숫자를 확인해요(360이면 모바일, 768 이상이면 넓은 모양).
2. `F5`로 새로 고치고, 그래도 그대로면 `Ctrl + F5`로 캐시를 무시하고 새로 고쳐요(Day 9).
3. 기기 모드가 꺼졌으면 왼쪽 위 휴대폰·태블릿 아이콘을 다시 눌러 켜요.

### 가로 스크롤이 생겨요 (화면 옆으로 밀려요)
- 관련: [P1 Day 13](#/day/p1-d13)

**원인:** 어떤 요소가 화면 폭보다 넓어서 오른쪽으로 삐져나와요. 흔한 원인은 폭이 고정된 요소(`width: 500px` 같은 값), 띄어쓰기 없이 아주 긴 글자, 그리고 `minmax`의 최소 폭이 화면보다 큰 경우예요.

**해결:**

1. 기기 모드 폭 360에서 화면을 오른쪽으로 밀어 어떤 부분이 삐져나오는지 봐요.
2. 개발자 도구 Elements에서 의심되는 요소 위에 마우스를 올리면, 그 요소의 영역이 화면에 파랗게 표시돼요. 화면 밖까지 나간 요소를 찾아요.
3. 고정 폭이 있으면 `max-width: 100%;`로 바꾸거나 지워요. 긴 글자가 문제라면 `overflow-wrap: break-word;`가 `body`에 있는지 확인해요.
4. 가로 스크롤 막대가 사라지면 해결이에요.

### 창 폭 숫자가 생각과 달라요 (Windows 디스플레이 배율)
- 관련: [P1 Day 13](#/day/p1-d13)

**원인:** Windows **설정 → 시스템 → 디스플레이**의 배율이 125%나 150%이면, 브라우저가 보는 CSS 폭은 실제 화면 픽셀 수보다 작아요. 모니터가 1920픽셀이어도 배율 150%면 CSS 폭은 1280px쯤이에요. 메뉴 이름은 Windows 버전에 따라 조금 다를 수 있어요.

**해결:**

1. 폭을 판단할 때는 모니터 해상도가 아니라 **기기 모드에서 입력한 숫자**(또는 개발자 도구에 표시되는 폭)를 기준으로 해요.
2. 기기 모드에서 360·768·1280을 직접 입력해서 확인하면 배율과 상관없이 같은 결과를 볼 수 있어요.

### 영상 칸이 작고 납작해요 (16:9가 아니에요)
- 관련: [P1 Day 13](#/day/p1-d13)

**원인:** `iframe`에 `class="video-frame"`이 없거나, CSS 규칙의 이름이 `.video-frame`이 아니에요. 그러면 iframe의 기본 크기(300×150)가 그대로 나와요.

**해결:**

1. `index.html`의 `<iframe` 뒤에 `class="video-frame"`이 있는지 확인해요(하이픈 `-`, 소문자).
2. `style.css`에 `.video-frame { … }` 규칙이 있고 `aspect-ratio: 16 / 9;` 줄에 빈칸이 슬래시 양쪽에 있는지 확인해요.
3. 저장하고 새로 고침해서 영상 칸이 가로로 긴 상자가 되면 해결이에요.

### 휴대폰에서 PC 화면이 깨알처럼 작게 보여요 (viewport 줄이 없어요)
- 관련: [P1 Day 13](#/day/p1-d13)

**원인:** `<head>`의 `<meta name="viewport" content="width=device-width, initial-scale=1">` 줄이 지워졌거나 오타가 있어요. 이 줄이 없으면 휴대폰이 약 980px짜리 가상 화면에 PC 모양으로 그린 뒤 줄여서 보여 줘요. 기기 모드에서 폭을 줄여도 CSS가 바뀌지 않는 것처럼 보일 수도 있어요.

**해결:**

1. `Ctrl + Shift + F`로 `viewport`를 검색해 다섯 페이지에 모두 한 줄씩 있는지 확인해요.
2. 없는 페이지의 `<head>`에서 `<meta charset="utf-8">` 줄 아래에 `<meta name="viewport" content="width=device-width, initial-scale=1">`를 넣어요.
3. 저장하고 새로 고침해서 줄바꿈과 글자 크기가 정상으로 보이면 해결이에요.

### 색이 모두 사라졌어요 (var 이름 오타, :root 문제)
- 관련: [P1 Day 14](#/day/p1-d14)

**원인:** `var(--이름)`에 쓴 이름이 `:root`에 정의한 이름과 다르거나, `:root` 블록의 중괄호 `{ }`가 짝이 맞지 않아요. 예를 들어 `var(--acent)`처럼 오타가 있으면 그 속성은 값이 없는 것으로 처리되어 그 색만 사라져요. 이름은 대소문자까지 같아야 해요.

**해결:**

1. 색이 사라진 곳의 규칙에서 `var(--…)` 이름을 찾아, `:root`의 이름과 한 글자씩 비교해요(`accent` / `acent`).
2. `:root {`로 시작해서 `}`로 끝나는지, 중간에 `;`가 빠진 줄이 없는지 확인해요.
3. 브라우저에서 `F12` → **Elements** → 색이 사라진 요소를 선택하고 오른쪽 **Styles** 창을 봐요. 오타가 있는 줄은 줄이 그어지거나 경고 표시가 붙을 수 있어요(표시는 버전에 따라 달라요).
4. 고치고 저장해서 색이 돌아오면 해결이에요.

### Pages 설정에 공개 저장소로 바꾸라고 나와요 (또는 Pages 메뉴가 없어요)
- 관련: [P1 Day 14](#/day/p1-d14)

**원인:** GitHub 무료 계정에서는 **공개(Public) 저장소**에서만 Pages를 쓸 수 있어요. 저장소가 비공개(Private)면 Pages를 켤 수 없다고 안내하거나 메뉴가 없어요.

**해결:**

1. 저장소 **Settings**를 열고 맨 아래로 내려가 **Danger Zone**(위험 구역)을 찾아요(화면 이름은 버전에 따라 달라요).
2. **Change repository visibility**(저장소 공개 범위 변경)를 눌러 **Make public**(공개로 바꾸기)을 골라요. 저장소 이름을 입력해 확인하라고 하면 입력해요.
3. 다시 **Settings → Pages**로 가서 7단계를 해요. 설정이 보이면 해결이에요.

### 주소를 열었더니 404 There isn't a GitHub Pages site here.
- 관련: [P1 Day 14](#/day/p1-d14)

```text
404
There isn't a GitHub Pages site here.
```

**원인:** 아직 배포가 끝나지 않았거나(처음에는 최대 10분), Pages 설정이 저장되지 않았거나, 저장소 맨 위에 `index.html`이 없어요. 영어 문장은 "여기에는 GitHub Pages 사이트가 없어요"라는 뜻이에요.

**해결:**

1. 10분쯤 기다렸다가 `Ctrl + F5`로 새로 고침해요.
2. **Settings → Pages**에서 **Branch**가 `main`, 폴더가 `/ (root)`로 저장되어 있는지 확인해요.

### for 괄호에서 Identifier 'i' has already been declared

1. `contents.js`의 `allVideos` 6줄에서 키가 모두 `youtubeId`(대문자 `I`, 소문자 `d`)인지 확인해요.
2. 개발자 도구 **Elements**에서 제목 링크 `<a href="…">`의 주소를 보면 `undefined`가 들어갔는지 확인할 수 있어요.
3. 고치고 저장해서 링크 주소 끝에 영상 ID 11글자가 보이면 해결이에요.

### 예시 영상이 "동영상을 사용할 수 없음"으로 보여요 (Day 20)
- 관련: [P1 Day 20](#/day/p1-d20)

**원인:** `aqz-KE-bpKQ` 같은 영상 ID는 **예시 값**이에요. 삭제됐거나 지역·공개 설정에 따라 볼 수 없는 영상일 수 있어요. 코드 오류가 아니에요.

**해결:**

1. 내 YouTube 영상을 브라우저로 열고 주소창의 `watch?v=` 뒤 11글자를 복사해요.
2. `contents.js`의 `allVideos`에서 `youtubeId` 값을 그 11글자로 바꿔요(홈의 대표 영상 `iframe`의 `embed/` 뒤 글자도 같은 방법으로 바꿀 수 있어요).
3. 저장하고 새로 고침한 뒤 제목을 눌러 내 영상이 열리면 해결이에요.
