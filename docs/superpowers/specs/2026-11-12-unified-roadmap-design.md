## 2. 이번에 확정한 결정 (사용자, 2026-11-11~12)

1. **작업 방식은 Native**: superpowers `executing-plans`로, 에이전트나 세션을 나누지 않고 한 세션이 한 마일스톤을 끝까지 한다.
2. **배포는 GitHub Pages**.
3. **범위는 155 Day 전부**와 사이트 전체.
4. **스크린샷 대조**: 375·768·1280 폭. 눈으로 대조한 뒤 승인된 화면을 기준 이미지로 저장하고 이후 자동 비교한다.
5. **접근안은 제자리 개편**: 기존 빌드·로직·테스트를 유지하고 스타일과 화면을 마일스톤마다 교체한다. 홈은 승인된 시안 코드를 옮겨 온다.
6. **진도 내보내기·불러오기**(다른 컴퓨터에서 이어 하기)는 필수 기능이다. 이미 설정 화면에 있다[측정: `views/settings.js`, e2e 2개]. 유지하고 새 디자인을 입히며 배포본에서 왕복을 확인한다.
7. 본문은 묶음마다 **작성 세션과 리뷰·수정 세션을 나눈다**.
8. P2·P3·SP에도 **핵심 그림을 최대 6개씩** 넣는다. "모든 Day 전용 그림"은 계속 보류한다.
9. Rust·PostgreSQL·Docker 같은 **도구 설치는 사용자 승인 뒤**에 한다.

## 4. 전역 제약

1. **토큰만 쓴다.** 색·글꼴·크기·간격·모서리·턱·모션 값은 `DESIGN.md`의 토큰(`var(--…)`)으로만 쓴다. 빌드 테스트가 토큰 파일 밖의 색 값(`#hex`, `rgb(`, `hsl(`)과 `font-family` 선언을 오류로 막는다. 새 값이 필요하면 `DESIGN.md` 수정안을 먼저 승인받는다.
2. **사이트 이름과 주소는 한 곳.** `textbook/content/curriculum.json`의 `title`(이름)과 `url`(공개 주소, M0에서 추가) 두 키가 유일한 원천이다. `template.html`의 `<title>`·`.brand` 대체값과 메타 태그는 빌드가 이 값으로 채운다. 코드와 본문에 이름·주소를 직접 쓰지 않는다. 빌드 테스트가 다른 곳의 주소 문자열을 막는다.
3. **파일 하나, 외부 요청 0건.** `index.html`을 더블클릭해도 동작한다. 글꼴·스크립트·그림은 모두 안에 넣는다.
4. **Named Rules를 지킨다.** One Pink, Paper Check, Real Progress, Label-Only Pixel, One Big Number, Solid Ledge, Press, Two Icon, Tooltip Raise.
5. **지어낸 수치를 넣지 않는다.** 화면의 모든 숫자는 진도 데이터에서 계산한다.
6. **외부 사실은 `docs/research/external-facts.md`에서만 인용한다.** 없으면 그 문서를 먼저 고친다.
7. 저장소 파일에 모델 식별자와 개인정보를 쓰지 않는다. 커밋과 push는 사용자가 요청할 때만 한다.

## 6. 데이터 흐름

**빌드 시점**
`curriculum.json` + Markdown → `lib/` 검증(섹션 순서, 블록 짝, 내부 링크, 용어 중복, `:::figure`의 id·캡션·대체 설명) → Day HTML(`<template>`), 검색 색인, 글꼴, 그림 코드, 앱 스크립트, 스타일을 `index.html` 하나에 넣는다. 검증 실패는 빌드 중단이다.

**실행 시점**
1. `main.js`가 내장 데이터 `cur`과 저장소의 진도를 읽고 `normalizeProgress`로 정리해 `prog`를 만든다.
2. 해시가 바뀌면 `router`가 경로를 정하고 화면 함수가 `ctx`만 보고 본문을 그린다.
3. 사용자가 누르면 `progress.js`의 순수 함수가 새 `prog`를 돌려준다 → 저장 → 셸과 본문을 다시 그린다.
4. 레벨·XP·지도 상태·"오늘"은 저장하지 않고 매번 `prog`에서 계산한다.
5. 완료 전후의 `prog`를 비교해 보상 사건(Day 완료, 레벨업, 월드 클리어, 해금)을 만들고 토스트·Modal에 넘긴다.
6. 저장 위치: 진도는 `localStorage` `wzh:v1:progress`, 테마는 기존 키, "세션에 한 번" 모션 기록은 `sessionStorage`. 그 밖의 상태는 저장하지 않는다.
7. 백업: 내보내기는 `prog`를 JSON 파일로 내려받는다. 불러오기는 파일 검증 → 덮어쓰기 확인 Modal → `prog` 교체 → 저장 순서다.

## 9. 배포

- GitHub Actions가 push마다 설치 → 단위·빌드 테스트 → e2e → 빌드 → Pages 배포를 한다. 테스트가 실패하면 배포하지 않는다.
- 액션: `actions/checkout@v7.0.1`, `actions/setup-node@v7.1.0`, `actions/setup-python@v7.1.0`, `actions/configure-pages@v6.0.0`, `actions/upload-pages-artifact@v5.0.0`, `actions/deploy-pages@v5.0.1`. 배포 job 권한은 `pages: write`, `id-token: write`[측정: `gh api …/releases/latest`, 각 README, 2026-11-12. `external-facts.md` 14.1]. 워크플로는 `.github/workflows/deploy.yml`.
- 배포본에는 **리뷰를 통과한 Day만** 넣는다. 나머지는 "준비 중" 화면이다(R55 유지). 목록 파일은 `textbook/content/published.json`(`{ "프로젝트 id": [처음, 끝] }`)이고 `npm run build:site`(`--published`)가 읽는다. 리뷰(R) 세션이 끝나면 이 파일에 범위를 한 줄 더한다.
- 저장소 루트의 `index.html`도 같은 규칙으로 빌드해 커밋한다(오프라인 사용).
- 공개 주소는 `curriculum.json`의 `url` 값이다.
- Pages 켜기와 첫 배포는 저장소 설정을 바꾸므로 M0에서 사용자 확인을 받고 한다.

## 10. 작업 방식 (Native)

- 마일스톤 하나 = 세션 하나 = 구현 계획 하나. `writing-plans`로 계획을 쓰고 `executing-plans`로 같은 세션이 실행한다. 서브에이전트와 자식 세션을 쓰지 않는다.
- 세션 시작: `CLAUDE.md` → `docs/CHECKPOINT.md` → 이 설계서 11장에서 다음 마일스톤 → 그 마일스톤 계획 순서로 읽는다.
- 세션 끝: 완료 기준을 증거(테스트 출력, 스크린샷, 공개 주소)와 함께 보고하고, `progress.md`에 `Mn: complete` 줄을 남기고, `CHECKPOINT.md`의 현재 위치를 고친다. 커밋·push는 사용자 요청에 따른다.
- 본문: 작성 세션(W)은 개요·CONTENT-GUIDE에 맞춰 쓰고 코드를 실행 검증한다. 리뷰 세션(R)은 새 세션이 초보자 눈으로 처음부터 따라 하며 CONTENT-GUIDE 체크리스트로 점검하고, Critical·Important와 막힘에 영향을 주는 Minor를 고친다. 나머지 Minor는 보류 목록에 적는다.
- 판정이 필요하면 `rulings.md`에 R63부터 이어 적는다.
- 화면을 바꾸는 마일스톤은 `DESIGN.md`에 없는 값이 필요해지면 멈추고 수정안을 승인받는다.

| 개편 중 옛 화면과 새 화면이 섞인다 | M0에서 토큰과 셸을 먼저 전부 바꾼다. 사용자 전달은 M14 이후다 |
| 기존 e2e 26개가 화면 개편으로 깨진다 | 화면을 바꾸는 마일스톤이 해당 e2e를 같은 세션에서 고친다. 동작 검증 내용은 줄이지 않는다 |
| 글꼴과 Three.js로 파일이 커진다 | 쓰인 글자만 서브셋, 3D 700KB 예산, 전체 16MB 미만을 빌드 테스트로 막는다 |
| 한 세션에 마일스톤이 안 끝난다 | 끝난 데까지 `progress.md`에 적고 남은 부분을 다음 세션이 이어서 한다. 마일스톤을 쪼갤 때는 완료 기준을 나눠 적는다 |
| 본문 작성 세션이 자기 글의 문제를 못 본다 | 리뷰는 반드시 새 세션이 한다. 통합 리뷰를 두 번(통독, 기술) 둔다 |
| 도구가 없어 P3·SP 검증이 막힌다 | E1을 콘텐츠 맨 앞에 둔다. 설치를 승인받지 못한 도구의 검증은 "미실행"으로 적고 Docker 없는 경로(R18)로 진행한다 |
| 외부 사실이 본문 작성 중에 낡는다 | W 세션이 쓰기 전에 `external-facts.md`의 해당 항목을 다시 확인한다. Q4에서 전수 확인한다 |
