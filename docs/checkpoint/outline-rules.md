# Rules for outline tasks (T8 P1, T14 P2, T21 P3, T29 SP)

The outline is the contract that lets several writers produce consecutive Days IN PARALLEL without reading each other's output. A writer of Day N sees only the outline, the reference code, the guide and Day 1 — so every Day block must state exactly what exists at the start of the day and what changes.

1. Format per Day: exactly the block in Task 8's brief (`## Day N — 제목 (minutes)` + 목표 / 이미 배운 것 / 시작 상태 / 오늘 만들/바꿀 파일 / 끝 상태 확인 / 과제 → 정답 요지 / 용어(사전 담당) / 자주 막히는 곳 후보) PLUS one more line: `- 레퍼런스 대응:` exact reference file paths/sections this Day's end state corresponds to (or "중간 단계 — 레퍼런스와 다름: …" when the Day builds a simplified version that a later Day upgrades; say which later Day).
2. "시작 상태" lists full Windows paths under the project folder; it must equal the previous Day's end state. Day 1 of P2/P3/SP starts from a clean folder and states which earlier-project knowledge is assumed (with links like `[P1 Day 25](#/day/p1-d25)`).
3. Every concept/tool/API a Day uses must appear in that Day's "이미 배운 것" or be introduced in that Day's 목표. No forward use.
4. Glossary: each term is owned by exactly ONE Day across the whole book. Before assigning a term, check existing glossary files in textbook/content/glossary/ (and other projects' outlines if present) — do not re-define a term another project owns; link to it instead. Write the owned terms' full entries (`### 용어` / `- 처음 등장: [P? Day N](#/day/p?-dNN)` / 2–4 sentence definition) in textbook/content/glossary/<pid>.md. Glossary headings are exact-case link targets for `[[용어]]`.
5. NEVER edit textbook/content/curriculum.json directly (ruling R32 — other outline tasks run in parallel). Write your project's entry to textbook/content/<pid>/_meta.json as `{ "project": { …full project object incl. days[{title,minutes,summary,keywords}] … }, "pages": [ …page entries to add, if any… ] }` using the exact curriculum schema (see the existing p1 entry in curriculum.json and textbook/lib/curriculum.mjs). minutes 60–120 (realistic for a 0% beginner at that point; Days with installs or long debugging get more). The controller merges it.
6. Verification you can run without the merge: validate your _meta.json against the schema by temporarily merging into a SCRATCH copy of the content dir (`cp -r textbook/content <scratch>/content`, merge there, `node textbook/build.mjs --check --allow-missing --content <scratch>/content`) — must report 0 errors (warnings for missing day files are expected). Never write the merged file into the repo.
7. Windows 11 + PowerShell + beginner realities must be scheduled explicitly in "자주 막히는 곳 후보" (install prompts, execution policy, ports, firewall, paths with spaces/Korean/OneDrive, CRLF, antivirus, etc.).
8. Write in Korean. No placeholders (TODO/TBD/작성 예정). NO GIT.
