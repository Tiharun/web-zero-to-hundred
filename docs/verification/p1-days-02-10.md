# 검증 기록: p1-days-02-10

- 검증일: 2026-11-06
- 환경: Linux 샌드박스, Node v22.23.4, Playwright Chromium(Windows 11 Edge와 같은 Chromium 계열), Git 2.43.0(교재의 `2.56.0.windows.4`와 다름. 명령과 출력 형식은 같고 버전 숫자만 달라요)
- 방법 요약:
  1. 각 Day 파일(`textbook/content/p1/day-02.md` ~ `day-10.md`)에서 📄 캡션이 붙은 코드 블록을 원문 그대로 꺼내(`docs/CONTENT-GUIDE.md` 6.2절의 `extract-blocks.mjs`와 같은 규칙) 스크래치 폴더에 재구성했어요. Day 파일의 블록이 학습자가 보는 코드예요.
  2. "오늘 끝 상태 전체 코드" 블록만 Day 1부터 차례로 쌓아 Day별 누적 끝 상태 폴더를 만들었어요. 아래 모든 브라우저 검사는 이 폴더(레퍼런스가 아니라 Day 파일의 블록)에서 했어요.
  3. 정적 서버(`tests/helpers/static-server.mjs`, Live Preview와 같은 http 방식)와 `file://`(더블클릭 방식) 두 가지로, 1280px와 360px에서 열었어요. Day 14 이전이라 `fetch` 페이지가 없어서 두 방식 모두 동작해야 해요.
  4. `(일부)` 블록은 앞 Day 끝 상태에 본문이 설명한 위치대로 적용해 다음 끝 상태와 같아지는지 비교했어요.
  5. Day 7의 `git` 명령은 powershell 블록을 원문 그대로 스크래치 저장소(로컬 bare 저장소를 `origin`으로)에서 실행해 "예상 출력"과 비교했어요.
- Windows 전용 절차(설치 마법사, 파일 탐색기·VS Code·GitHub 화면)는 이 환경에서 실행할 수 없어서 아래 표에 `대조`(공식 문서 대조) 또는 `미검증`으로 적었어요. 설치 화면 문구는 모두 "버전에 따라 다를 수 있어요"를 붙였어요.
- 브라우저 검사 총 111건, 모두 통과. 콘솔 오류 0(외부 YouTube 요청은 샌드박스에서 막아서 `iframe` 재생은 확인하지 못했어요).
